# How does the evidence identity bind bounded pages?

Blocked by: #5, #8
Type: Grill

### Question

Should a versioned canonical manifest bind ordered descriptors, metadata, source hashes, and page hashes into the expected evidence identity?
This candidate avoids a full-body hash for every page.
The consumer must first verify the complete manifest against the trusted preparation identity.
It can then verify each returned page against that manifest.
The manifest itself must have bounded retrieval, including an oversized descriptor.

The selected contract must fix the canonical format and independent verification rule.
It must distinguish a verified page from verification of every artifact byte.
No page or final cursor alone proves complete delivery.
The byte-delivery probe establishes feasibility but does not approve this public format.

### Answer

The logical manifest uses a versioned Bench profile of the existing flat-table TOON representation.
The profile fixes block, column, and row order, scalar types, escaping, indentation, and final newlines.
The profile uses the existing encoder rather than a second custom text serializer.
Typed string cells preserve numeric-looking digests and source identifiers.
An encoder change that alters canonical bytes requires explicit format compatibility handling.
The reader rejects a malformed or unsupported profile.

The identity hashes the complete canonical manifest bytes.
The manifest binds selectors, source pins, roles, paths, requiredness, metadata, source hashes, and ordered page hashes.
Page descriptors bind logical byte offsets and lengths.
Source bytes remain exact, without normalization.
The physical container remains separate from the logical manifest contract.

The manifest itself supports bounded retrieval.
The expected identity comes from trusted preparation or a verified handoff.
An independent consumer reconstructs and hashes the manifest before it trusts descriptor membership.
Each page read verifies the manifest and requested page against that expected identity.
Full artifact verification checks every stored page and source digest.
A verified page does not certify unread pages or complete consumer delivery.

The [encoding comparison](../assets/research.md#manifest-encoding-comparison) records the source evidence and measurement limits.
No token-savings percentage forms part of the accepted contract.
Production validation must cover the canonical TOON manifest and its bounded reconstruction.
The existing byte-delivery probe does not establish that complete manifest behavior.
