# Which commands own delivery, reuse, and current validation?

Blocked by: #6, #8, #9
Type: Grill

### Question

Which exact prepare, read, verify, and cleanup commands should the stateless contract expose?
The command contract must distinguish artifact integrity from delivered context and current action prerequisites.
It must define the default next-page sequence, explicit source navigation, terminal states, and resumable verification evidence.
It must also define unchanged-source reuse, fresh-consumer retrieval, and source-movement refusal.
The canonical phase owns action prerequisites, while preflight owns its executable retrieval sequence.

### Answer

The charge flag explicitly prepares persistent evidence.
Ordinary preflight without that flag remains read-only.
The command grammar is:

```text
bench preflight build <slug> --charge --ticket <basename> --base <b> --source-tip <t> [--max-store-bytes <n>]
bench preflight review <slug> --charge --base <b> --source-tip <t> [--max-store-bytes <n>]
bench preflight evidence <id> [--source <source-id>] [--cursor <cursor>]
bench preflight evidence <id> --verify
bench preflight evidence <id> --check-current
bench preflight evidence-clean [--cursor <cursor>] [--apply <fingerprint>]
```

Preparation returns the expected evidence identity and the first required retrieval action.
Default traversal returns the complete manifest, required metadata, canonical sources, and generated evidence in their declared order.
Each read returns an exact next action or an explicit stream end.
A source selector names a prepared source identifier, not an arbitrary path.
The consumer verifies complete page coverage from actual results; a final cursor alone proves no such coverage.
The owner stores no consumer reading log or server progress session.

The verify operation proves stored evidence integrity and membership.
The check-current operation validates the current assignment and source pins.
Neither operation certifies consumer delivery, comprehension, reviewer approval, or the task supplement.
The phase keeps the action prerequisites recorded in ticket 9.

A retained consumer can reuse unchanged verified content that remains available in its required context.
Reuse requires verification of source identity, role, requiredness, and membership in the new evidence set.
A fresh consumer retrieves its required context.
Reading an existing artifact never reruns its collectors.
A new preparation collects generated review evidence again.
A moved source invalidates the previous action binding, even when historical bytes remain readable.
