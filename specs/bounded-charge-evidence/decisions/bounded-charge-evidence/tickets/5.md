# Does bounded retrieval preserve the exact prepared evidence bytes?

Blocked by: #3
Type: Prototype

### Question

Can separate bounded retrieval calls reconstruct the selected artifact's exact evidence bytes and verified source membership?
The probe compares both proposed response budgets without selecting either one.
It covers oversized source bodies, metadata, numeric-looking digests, hostile paths, and missing final newlines.
It also distinguishes complete byte coverage from a receipt that merely names the final page.
The [validation plan](../assets/research.md#verification-record-and-remaining-evidence) records the remaining evidence.

### Answer

The reviewer accepts the byte-delivery result as sufficient shaping evidence.
Production validation must cover bounded manifest delivery, encoding expansion, the verification interface, and supported harness transports.
The result does not prove comprehension or approve the remaining protocol details.

### Prototype observation

The disposable Linux probe used the actual Bench TOON encoder and its pinned decoder.
Each page came from a separate process.
Eight sources reconstructed exactly across 100 reads under each candidate budget.
The largest encoded response contained 21,829 bytes.
The total encoded delivery contained 1,686,812 bytes for each budget.
Both the 48,000-byte candidate and the 60,000-byte candidate passed the measured bound.

The sources included the five baseline build sources, a large ticket, generated review bytes, and 5,000 metadata entries.
The probe preserved Unicode, escaping, hostile path text, numeric-looking digests, and a missing final newline.
Missing pages, duplicate pages, and a final page without earlier pages failed complete-source verification.
A changed role changed the evidence identity.
A changed stored page failed its digest check.
An unsupported control character failed representation checks.

The candidate manifest bound ordered source descriptors and page digests.
The manifest contained 8,197 bytes and stayed local to the probe.
The probe did not test bounded manifest delivery, the worst possible encoding expansion, or a production receipt interface.
It did not exercise a supported harness transport or prove consumer comprehension.
Its source-offset lookup was intentionally simple and supplies no performance claim.

The result supports exact byte delivery through separate bounded calls.
It does not approve the format, budget, action prerequisites, or production protocol.
The Answer section records the reviewer's acceptance and the required production checks.
