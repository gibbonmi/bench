# Bound the staged index blob during the read

Blocked by: none

## What to build

`git.IndexBlob` reads a whole index blob through `git.Raw`, which buffers all of `git show` stdout. `readIndexBlob` in `internal/gate/gate_prose.go` then grades the size through `bounds.Read` after the whole blob is in memory. A staged blob of any size is therefore read whole before the control-record bound applies.

Bound the stream during the read. Give the git package a reader form that starts `git show :<path>` with a stdout pipe and returns the stream. `readIndexBlob` feeds that stream to `bounds.Read` with `bounds.ControlRecordLimit`, so the read stops at limit plus one byte. It then classifies the result as it does today. The reader form closes the pipe and reaps the child after the bounded read. An oversized blob then leaves no child process, and no broken-pipe error masks the oversized verdict.

A `git show` that exits non-zero on a missing path still returns the same error text shape as today.

Keep `TestGateProseStagedRefusesAnUnboundedBlob` green with no edit. Add a git-package test that stages a blob of three times the limit. The test reads limit plus one bytes through the stream, closes it, and observes no error and no hung child. The existing `TestIndexBlobReadsTheIndexNotTheWorkingFile` keeps its assertion over the same reader.

Line: opus / medium, two implementation iterations.
Self-probe: swap the pipe for a whole-blob buffer read behind the same reader form, and report which test observes the change. If no test observes it, report that the seam is only observable through memory, and keep the stream form.
