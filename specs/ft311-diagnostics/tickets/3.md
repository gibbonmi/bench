## What to build

Add the `--staged` form to `bench gate-prose <root>`.
The grammar becomes `bench gate-prose <root> (--staged | [--] [path...])`, and the help adds `example: bench gate-prose . --staged`.
`--staged` beside a path or a `--` is a usage error at exit 2.
A root that is not the top of a Git working tree answers a `prose:` refusal line on stdout at exit 1.

The Git adapter gains two readers.
One lists the index entries that differ from HEAD with their modes, through `diff --cached --name-only -z --diff-filter=ACMRT --no-renames` and `ls-files --stage -z`.
The other reads one index blob through `show :<path>`.
The staged form keeps the regular-file entries whose name ends in `.md`, reads each blob, and grades the bytes.

The exclusion policy comes from the index blob of the exclusion file, and an absent entry answers the absent-policy diagnostic.
The policy constructor validates each exclusion target against the index entry list, never against the working tree.
An index entry is a file row, a prefix of index entries is a directory, and anything else is an absent path.
On an unborn branch every index entry is staged.
The prose grader gains a policy-from-bytes constructor and a bytes entry point, and it keeps one parser.

The pass table, the exit meanings, the named-path form, and the lane's prose argv do not change.
This is the last ticket that touches the prose and gate packages, so run both focused suites.

Line: gpt-5.6-terra / medium, three implementation iterations.
Self-probe a swap of the index blob read for a working-file read and report the observed red on the differing-file case.
The coordinator independently omits the mode filter at another site.
