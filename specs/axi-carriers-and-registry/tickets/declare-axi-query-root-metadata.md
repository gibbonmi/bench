## What to build

This ticket introduces the AXI declaration type in `cmd/bench/command_registry.go`
— one record per production command member carrying name, process attachment, AXI
disposition, grammar/help owner, renderer family, empty class, applicable detail
modes, and applicable shared routes — plus the validator that refuses a record
with any required field unset. It then declares the twenty in-process query roots:
the `commandRegistry` entries in `cmd/bench/main.go` that carry no `Attachment`
(`anchors` through `test`). Declarations are inert: nothing in dispatch or
rendering reads them in this ticket.

Membership is derived, never transcribed: the owner test walks the real
`commandRegistry` slice, selects the attachment-less entries, and requires one
declaration per entry, so a root added later is red until it is declared.
Totality across all 48 roots and the nested families is not asserted here — the
later declaration tickets add their own families and `validate-axi-registry.md`
owns the whole-registry completeness refusal — which is what lets this ticket
land green alone.

## Acceptance

- [ ] [RQ1] (covers CR5) every attachment-less root in `commandRegistry` has exactly one declaration record and every required metadata field on it is populated.
