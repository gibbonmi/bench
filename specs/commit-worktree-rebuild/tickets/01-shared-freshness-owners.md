## What to build

The landing keeps two freshness rules in `internal/worktree`: the diff test `brokerSourceChanged` (`internal/worktree/land.go:350-375`) and the verify, build, and second-verify sequence of `refreshBroker` (`internal/worktree/land_effects.go:148-174`). The commit step of ticket `02-commit-rebuilds-worktree-build.md` needs both rules, so this ticket moves each rule into one exported owner in `internal/freshness`. The spec section "The shared owners" states each rule.

`freshness.DiffChangesBuildInputs(root, base, tip string) bool` goes into `freshness_buildinputs.go`. It reads the diff once, as `git diff --no-renames --name-status base tip`, through `internal/git`. It answers true when the diff names a path of `BuildInputs(root)`. It also answers true when the diff deletes, with status `D`, a non-test `.go` file in the directory of a package that `go list -deps ./cmd/bench` lists for `root`. The package directories come from the same `go list` call that `buildInputs` makes; split that call in place and add no second JSON decoder (`internal/conformance/strict_json_owner_test.go:299` names `freshness.buildInputs` as an exclusion). A root that declares no build inputs, an input set that does not resolve, and a diff that does not read each answer false. `brokerSourceChanged` goes away, and its callers at `internal/worktree/land.go:193` and `internal/worktree/land_stack.go:85` call the owner. `land_stack.go` then imports `internal/freshness`. `land.go` drops its `strings` import, because `brokerSourceChanged` is its one user.

`freshness.Refresh(ctx context.Context, root string, build func(context.Context, string, string) error) (rebuilt bool, buildErr, err error)` goes into `freshness_verify.go`. Ticket 02 passes `runbinary.BuildSubject` as `build`. It returns `false, nil, nil` with no build call when `Verify(root, PublishedExecutable(root))` passes. Otherwise it calls `build(ctx, root, PublishedExecutable(root))` once, keeps that error as `buildErr`, reads `Verify` a second time, returns that answer as `err`, and returns `rebuilt` true only when `err` is nil. `Refresh` holds no held-install branch. `PublishedExecutable` keeps its spelling, because `internal/conformance/build_contracts_test.go:19,306` parses it.

`refreshBroker` keeps its not-applicable branch, its held-install branch before the call to `Refresh`, its two stderr texts (`landing refresh build failed: ` before a non-nil `buildErr`, `landing refresh failed: ` before a non-nil `err`), its effect results, and its signature (`internal/worktree/land_effects_test.go:309` calls it). Its doc comment moves to the owner where it describes the sequence.

A landing whose reviewed diff only deletes a non-test Go file of a listed package now reports the install step of a broker-changing landing. Add one `CHANGELOG.md` entry under `## [Unreleased]` for that change. Ticket 02 adds its own entry later.

The owner tests go into `internal/freshness/decision_test.go`. That file is a `directArchitectureTests` entry (`internal/conformance/ordinary_build_census_test.go:156`), so it starts no `exec.Command` and calls no `CommitAll`, `InitRepo`, or a `Run`/`Output` with an `init`, `clone`, or `worktree` literal (`:79`, `:310-319`). Build each Git fixture with `gittest.RepoOnBranch`, `gittest.MustRun`, and `gittest.Commit`; a committing test takes `RepoOnBranch`, which sets an identity (`internal/gittest/gittest.go:18-24,174-181`), and `internal/freshness/publication_topology_test.go:15,66` already imports `gittest`. `kittest` imports `internal/freshness`, so these internal tests use `writeBuildFixture` and `writeBuildFixtureAt` (`freshness_digest_test.go:282,287`) and `writePublishedFixture` (`freshness_verify_test.go:338`). `freshness_digest_test.go` is in `Writes:` because a fixture helper for a second `cmd/bench` Go file sits beside those helpers. `freshness_verify_test.go` is in `Writes:` because it calls `buildInputs` at `:39`, so a signature change of that function reaches it. A fixture for a deletion or a rename needs a second non-test Go file in its `cmd/bench` package. The CW49 fixture renames that file with its content unchanged, so Git's rename detection fires without `--no-renames`. A fake build publishes with one `freshness.Publish` call, as `internal/treetarget/build_test.go:52` does.

The CW44 landing test goes into `internal/worktree/land_broker_notice_test.go` (152 lines). Its fixture adds a second non-test Go file to `cmd/bench` beside the one that `writeGoMainFixture` writes (`internal/worktree/land_effects_test.go:24-31`). The test calls `t.Parallel`. `internal/worktree` pins its exact top-level test count (`worktreeTestCount`, `internal/worktree/parallel_census_test.go:922`), so raise that pin by one in this ticket.

Line budgets: `internal/worktree/land_stack.go` is 394 lines and gains one import line. `internal/worktree/land_effects_test.go` is 376 lines, `internal/freshness/freshness_verify_test.go` is 393 lines, and `internal/freshness/freshness_digest_test.go` is 380 lines, so add no test to those three files. `internal/freshness/` holds 12 source files at its maximum of 12, and `internal/worktree/` is far above its maximum, so add no file in either directory. Add no literal that holds `next=`, `next[`, `run bench `, or `"; then "` in `internal/worktree` (`internal/conformance/registry/route_bypass.go:25`).

## Acceptance

- [ ] `DiffChangesBuildInputs` answers true for a diff that names `scripts/go-build.sh`, and false for a diff that names only `README.md` (CW01, CW02).
- [ ] `DiffChangesBuildInputs` answers false for a root with no `scripts/go-build.inputs` (CW03).
- [ ] `DiffChangesBuildInputs` answers true for a diff that only deletes a non-test `.go` file of a listed `cmd/bench` package, and false for a diff that only deletes a `_test.go` file there (CW41, CW42).
- [ ] `DiffChangesBuildInputs` answers true for a diff that only renames such a file to a `_test.go` name with its content unchanged (CW49).
- [ ] `Refresh` calls no build over a fresh published build, calls the build once over a stale or absent one, and returns `rebuilt` true with nil errors after a build that publishes a valid seal (CW04, CW05, CW08).
- [ ] `Refresh` returns `rebuilt` false and a non-nil `err` after a build that returns nil and publishes nothing, and returns a failing build's error as `buildErr` (CW06, CW07).
- [ ] A broker-changing landing, a deleted-input landing, a stale-destination refresh, a failed refresh, a fresh broker, and an installed candidate keep or gain the answers that CW09, CW11, CW12, CW44, CW46, and CW47 state.
- [ ] `internal/worktree/land.go` and `internal/worktree/land_stack.go` hold no local diff intersection with `BuildInputs` (CW10).
