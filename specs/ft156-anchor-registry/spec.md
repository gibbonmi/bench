# ft156-anchor-registry

Status: staged

Decision source: `specs/ft156-anchor-registry/decisions/ft156-anchor-registry.md` — ready compiled map, staged program resolved 2026-08-02; the `ROADMAP.md` FT156 row that directed this entry (reviewer direction 2026-08-03) carries the drained `Contracts:`-line false-green rider this spec also closes. The map's `## Sources` section is empty, so there were no structured entries to re-read; every load-bearing map claim was re-verified against the current tree instead. Two figures drifted since the map: the anchor helpers file measures 873 lines (not 864) against its 660 grant, and the 299-needle census predates the ticket-template anchors added afterward — the build re-derives the count at migration time rather than trusting either figure.

## Problem

The conformance anchors that pin the kit's guidance prose are weaker than they look, and invisible to the people editing under them. A guidance sentence can be commented out and still satisfy its require-direction anchor, because only `forbid` strips HTML comments. The ~300 anchors live as hand-written inline closures in one conformance test file that stands 213 lines over its structure grant and that `cmd/bench` cannot import, so an editor about to touch `.bench/BENCH.md` has no way to ask which anchors pin it. Two proven coverage holes sit in the same mechanism: no fixture exercises the generic section-scoped anchor helpers over `.bench/BENCH.md` (the one existing `.bench/BENCH.md` fixture is graded by the bespoke structured-phase parser instead), and deleting only the ticket template's `Contracts:` line passes the real graded-root conformance run — a recorded false green.

## Solution

The anchor set becomes declarative data with one shared matcher, in a package the CLI can read. `bench anchors <path>` then answers the pre-edit question directly. With matching centralized, the comment-strip asymmetry becomes one matcher change plus a red demonstration instead of a ~220-anchor sweep. The two coverage holes close first — they are independent, cheap, and the prose passes that edit `.bench/BENCH.md` land on top of them — and any surviving claim that a substring anchor defeats paraphrase is restated to what substring matching actually proves.

## User stories

1. **A kit editor relocating a section-owned rule inside `.bench/BENCH.md` turns the gate red.** A canary fixture in the `workflow-guidance-anchors` family moves the fix-don't-park sentence out of the Workflow section (keeping it in the file, so the shared-rule presence check stays green) and expects the Workflow-section placement diagnostic — the first fixture to exercise the generic section-scoped helpers over `.bench/BENCH.md`. It is authored against the current mechanism and needs no rewrite when the registry lands, because fixtures are data graded from outside the mechanism.
   `Line: sonnet / low.` Exact target, 69 sibling fixtures as prior art, and the canary sweep makes the red observable.
2. **Deleting the ticket template's `Contracts:` line turns the gate red.** A section-scoped require pins the template's `Contracts:` line inside `craft-tickets`' "Write one file per ticket" section, closing the recorded false green; a canary fixture deletes exactly that line and expects the new diagnostic. TDD-shaped: the fixture lands first and the sweep stays red until the anchor exists.
   `Line: opus / medium.` Unlike story 1 this edits the conformance check itself, and the profile caches gate/conformance logic at mid.
3. **An editor queries which anchors pin a file before editing it.** The anchor set moves into an ordered declarative table in a new non-test package below the conformance import edge, with one shared matcher; the conformance suite consumes the table, and `bench anchors <path>` renders the anchors pinning a path as a TOON table on the AXI contract. The helpers file returns under its 660-line grant, and a recorded needle-inventory equality check (pre-extraction enumeration versus registry rows, tuple-wise including diagnostics) is the migration receipt.
   `Line: opus / medium.` The migration edits the oracle and a silently dropped anchor is only sample-covered by fixtures, so the weak-gate signal bumps it from cheap.
4. **A commented-out anchored sentence turns the gate red.** The shared require-direction matcher strips HTML comments exactly as `forbid` already does, preceded by a sweep proving no current kit anchor is satisfied only inside a comment; a canary fixture comments out an anchored sentence and expects its missing-anchor diagnostic. TDD-shaped: the fixture lands first and stays sweep-red until the strip lands.
   `Line: opus / medium.` One matcher change, but it moves oracle semantics across every require-direction anchor; the profile caches conformance logic at mid.
5. **No surviving claim overstates what a substring anchor proves.** Sweep the registry's diagnostics and comments, the staged specs' coverage rows, and the profile for claims that an anchor closes paraphrase evasion; restate each to the weaker placement-and-presence claim substring matching actually delivers.
   `Line: fable / high.` The sweep edits `projects/benchkit.md` and other always-loaded prose, which is `craft-line`'s leverage override; flagged for reviewer veto since it routes the top row.

Stories run in order: 1 and 2 are the pulled-forward coverage floor, 3 is the mechanism move, 4 rides 3's matcher, 5 rides 4's landed strength. All five share one owner — the anchor mechanism and its consumers — so the partition check finds no disjoint package groups and the program lands as one spec (map discretion exercised; the map's own note that the per-anchor-sweep premise behind a separate comment-strip spec no longer holds once the matcher is shared).

## Implementation decisions

- **The registry package.** A new non-test package (working name `internal/anchors`) below the conformance import edge, mirroring `internal/conformance/registry`'s posture: it imports nothing from `internal/conformance` and documents the edge. It owns the anchor type — file, kind, section (empty for whole-file), needle, diagnostic — the ordered table, the shared matcher, and evaluation against a root: it reads the anchored files itself and emits diagnostics byte-identical to today's (missing-file, missing-section, duplicate-section, and per-anchor texts), because canary EXPECT matching is substring-based and the diagnostic byte-shape is load-bearing.
- **Four kinds, one matcher.** `require`, `forbid`, `require-in-section`, `forbid-in-section`. The plain and collapsed require paths merge: matching collapses whitespace on both text and needle, so a needle authored with incidental double spacing cannot silently stop matching. Case folding remains a property of the in-section kinds, as today. Story 4 then adds HTML-comment stripping to the require direction inside this one matcher.
- **What stays behind.** The bespoke non-needle checks — the structured-phase contract parser, the README layout checks, the what-next count check, the implement-spec conditional substring checks — remain code in the conformance package. The registry holds only the uniform needle anchors. The fence-aware markdown H2 section parser moves into the new package with its recorded-proof test, since section resolution is matcher behavior.
- **`bench anchors <path>`.** One positional argument, resolved to a repo-relative slash path (a cwd-relative path that exists, or the repo-relative literal). Output joins the AXI query surface: the shared flat-table TOON emitter with columns kind, section, needle; a definitive empty state for a path no anchor pins; structured errors on stdout with exit 0/1/2. The query answers from the compiled table, never the disk, so it works for a file about to be created and is unaffected by a deleted target. Registered in the `cmd/bench` command map and the subcommand routing registry, routed in `bin/bench.sh` with a help-grammar line, and added to `.bench/BENCH.md`'s CLI Inventory among the query commands.
- **Migration verification is a receipt, not a standing check.** A permanent count or needle-equality test would be a second derivation of the registry (the one-source-per-fact standard), so the pre-extraction inventory (instrumented enumeration of every closure call, tuple-wise with diagnostics) is compared against the registry once at the migration commit and recorded in the build evidence. The standing regression net is the existing fixture family plus the structure shrink: the helpers file cannot return under 660 lines while a private copy of the needle data survives in it.
- **No grant raise.** The map rules the ~850 stopgap out once this lands; the extraction itself is what returns `internal/conformance/docs_workflow_helpers_test.go` under its existing 660 grant, and the spec adds no new `bench structure` findings. `.bench/structure.budgets` is reviewer-owned (`craft-seams`), so raising the grant is not a route open to the build at all — the ruling is enforced by ownership, not by a coverage row.

## Testing decisions

- Good tests here exercise the three externally observable behaviors: a mutated kit tree reds the graded conformance run with the exact diagnostic (bite), the query command reports the anchors pinning a path (visibility), and matcher semantics — collapse, case fold, section resolution, comment strip — hold for hostile shapes (fenced headings, unclosed fences, comment-wrapped sentences).
- Seams receiving tests: the graded-root conformance seam via canary fixtures (prior art: the `workflow-guidance-anchors` family, 69 fixtures); the new package's matcher seam via unit tests (prior art: `TestMarkdownH2SectionsSkipsFencedHeadings`, which moves with the parser); the CLI seam via an AXI contract fragment (prior art: the existing `internal/contract/axi` fragments and the AXI phase's fixture repos).
- Gate seams observing the feature: the conformance phase (`TestRootConformance` over the graded root) grades the anchors; the canary phase proves they still bite; the AXI phase grades `bench anchors`; the subcommand-routing and bench-sh-routes conformance checks refuse an unrouted entry point, so every shipped surface reaches the same implementation.

Red-signal cadence: this spec is staged, so no signal has run yet; an `observed red` row follows `craft-tdd`'s cadence — the signal runs and fails immediately before its slice is implemented, and the build claims the row only after observing that red (or, for the standing-tripwire row above, the sweep-observed red on the mutated tree).

Quantifiers enumerated: "every anchor tuple" in the migration row means the build-time instrumented enumeration of all closure calls in the helpers file at the migration commit — not the map's stale 299 — at per-tuple granularity. "All 69 fixtures" means the `workflow-guidance-anchors` family as it stands at build time, plus the two fixtures stories 1–2 add.

Degenerate implementations named: a fixture whose EXPECT matches a diagnostic any failure prints is rejected by the canary baseline's vacuous-EXPECT check (stories 1, 2, 4); the sequential-port degenerate for story 3 — registry serving the CLI while conformance keeps private closures — is caught by the structure row and the migration receipt being taken from the registry the conformance run imports; the always-green stub for `bench anchors` is caught by the fragment's real-content rows.

### Edge inventory

- A path argument containing spaces or glob characters resolves to no registry key and takes the definitive-empty-state row above; nothing globs, nothing executes.
- A flag's value read as a positional, extra arguments, and unquoted multi-word arguments take the structured-error row above.
- cwd deeper than the repo root takes the subdirectory row above.
- Fenced and unclosed-fence markdown headings inside anchored files: already covered — the section parser's recorded-proof test moves with it.
- **Won't handle:** paraphrase evasion — the map's closed deferral (2026-08-02): re-priced only after the FT107/FT100 prose passes and FT158's falsification evidence, not to be reopened by this spec.
- **Won't handle:** absent-versus-empty target file divergence — the query answers from the compiled table by design, never the disk, so both states answer identically; the distinct-behavior edge does not exist on this surface.
- **Won't handle:** re-run idempotency, interrupts, and process-boundary lifecycle for `bench anchors` — a read-only command over compiled data holds no state to disturb, serialize, or reload.
- **Won't handle:** special files, dangling symlinks, and trailing-newline damage in the query path — the command reads no discovered files; conformance evaluation keeps today's `exists`/read posture for anchored files, unchanged by this spec.
- **Won't handle:** control bytes in the path argument — the shared TOON emitter already refuses control bytes in rendered text, and registry needles are kit-authored single-line literals; no new sink is introduced.
- **Won't handle:** a prompting/non-TTY posture — the command never prompts.

## Out of scope

- **A stronger-than-substring matching mechanism.** Deferred by the 2026-08-02 decision session; re-price after FT107/FT100 settle the surface and FT158's passes show whether real paraphrase evasion occurs. Unpriced by that ruling, and not reopenable here.
- **Anchor authoring tooling** (a lint or `bench anchors --add` path for proposing new anchors at edit time). A separate capability with its own future spec: ~10 edits, 2 gate runs.
