## What to build

The FT463 admission took two landings. `bench commitment plan` read every source that is not a new deliverable at the default-branch tip. So a new outcome whose roadmap row the same landing adds refused with `missing or nonregular tree file`. The row landed first, and the admission landed second, with a second gate.

A new outcome source now reads the checkout HEAD when the current policy names no source at its path and the default-branch tip definitely lacks that path. Every other source keeps the default-branch tip, so a worktree edit of a row cannot pass as current.

The known-issues row for a nested exec spill names the `--in` route, which bounds the response once. FT341 owns the retirement of that row.
