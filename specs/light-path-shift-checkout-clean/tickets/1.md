# Accept a shift checkout in the explicit branch-discard clean

Blocked by: none

Covers: none

## What to build

A `bench shift` can leave a pooled worktree with a `bench/shift-*` branch
checked out instead of its assignment branch. Today the explicit clean retains
that tree with the reason "assignment does not match current branch", and no
verb checks the assignment branch out again. The operator cannot remove the
worktree through Bench.

Teach the explicit ordered eligibility decision one narrow exception. When the
operator passes `--discard-branch`, and the checked-out ref sits in the shift
namespace that `intent.ShiftBranchPrefix` names, the branch mismatch no longer
retains the tree. Every other check stays in its order: the lock agreement, the
lease, the nested state, the ignored residue, and the recovery promotion. A
mismatch onto any branch outside the shift namespace still retains. The
automatic sweep and the `--landed` set never see the exception, because they
plan with empty options.

Add the two facts the decision needs to `ExplicitFacts`: the discard-branch
option, and whether the registration's branch ref is a shift branch. The
explicit planner in `subshell.go` gathers both. The decision in
`DecideExplicit` reads them and performs no I/O. The existing override then
names the checked-out shift branch for deletion, as it does today. After the
apply, the assignment branch is unclaimed, and the `--unclaimed` form retires
it.

Pin the new row in `TestExplicitEligibilityOutcomeMatrix` beside the existing
branch-mismatch row. Add one worktree-level test in `clean_branch_test.go`
that builds an owned assignment, switches its checkout to a shift branch, plans
with `DiscardBranch`, and applies. The test proves the checkout is gone and the
shift branch is deleted. The existing "assignment identity mismatch" case keeps
its non-shift branch and keeps its retain verdict.

The three files `lifecyclepolicy.go`, `lifecyclepolicy_test.go`, and
`subshell.go` are over the structure budget. The lane grades growth against
the tip, so each edit lands at or below the file's current line count. Trim
comment prose in the same file to make the room.

Record the change under `## [Unreleased]` / `### Changed` in `CHANGELOG.md`,
in the shape of the entries above it.
