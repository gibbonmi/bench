# How does the reader table cover a read that a child process makes?

Blocked by: #7, #10
Type: Grill

### Question

A child process can read a covered path while the test log of its parent
records nothing. How does the reader table name such a reader, and what turns
a missed child reader red?

### Answer

The reader set always runs the `system` phase. One declared child-reader list,
beside the derivation of the reader table, names the other child readers. Each
row is one pair of a test package and a covered family, and the rows join the
derived rows. Today the list holds one row: `internal/releaseevidence` with the
`CHANGELOG.md` family. So that package runs only when `CHANGELOG.md` changes.

The derived table and the declared list state different facts, so neither
copies the other. The whole run under the bound of #8 is the only detector of
every missed reader: a child reader, a reader that tolerates a failed read, and
a reader whose read depends on content outside the changed family. #9 routes
its red.
