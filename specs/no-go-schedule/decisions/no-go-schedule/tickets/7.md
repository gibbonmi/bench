# Who owns the census, and how is it derived?

Blocked by: #2, #5
Type: Grill

### Question

The census can be a declared table or a table that a traced whole run derives.
It can also be a declared table that each whole run verifies against its trace.
Which owner holds the census, and what turns a missed reader red?

### Answer

Each whole gate run derives the reader table from its own trace. The run records
one Go test log for each test package through a shim on its one `go test` call.
It then maps each package to every covered path family of each `open` or `stat`
entry outside the package's own directory.

Before the family mapping, the derivation resolves each logged path through
every tracked symbolic link on its prefix. The family of the target counts. For
example, a read of `.claude/commands/x.md` is a read of `.agents/`.

A landing reads the reader table of the last whole green. The run derives no
table, and the next landing runs the whole gate, in each of these cases:

- A log is missing or does not parse.
- The table does not name `internal/conformance` as a reader of every covered
  family. This witness rejects an empty or short trace.

No declared table of in-process readers exists, so no hand list can miss one.
The test log flag is private to `cmd/go`. A toolchain change that breaks it
therefore sends every landing to the whole gate, and never to a stale or empty
table.
