## What to build

Give the landed selector one scope value beside its cleanup options.
An empty value keeps the whole-repository scope the explicit route already uses.
A non-empty value is the landing's destination base.
A row then qualifies only when the landed proof holds against the published commit and fails against that base.
Call the existing landed proof owner for both questions and add no second proof.

Add the cleanup effect to the landing effect owner, after the refresh effect.
Widen the row ticket 1 prints from `effects[1]{effect,result}` to `effects[2]{effect,result}`.
The added `cleanup` cell reads `complete`, `failed`, or `pending`, and a failed refresh leaves it `pending`.
The widening moves ticket 1's own expectations, so this ticket also owns `TestLandRefreshesTheBrokerAfterPublication`, `TestResumeLandCompletesTheUnfinishedEffects`, and `TestLandEffectsRowPrecedesTheLandedRecord`.
Each of those three reads the `effects[1]` bytes today, and each reads the `effects[2]` bytes after this ticket.

The landing plans the narrowed set, applies it in the same process, and prints no fingerprint and no apply action.
Every selected row still passes the existing eligibility verdict, and a row whose eligibility is not proved is retained.
The apply re-plans each row before it touches that checkout and stops the set on the first drift, exactly as the explicit route does.

Print the plan rows on stderr, beside the landing's other evidence, so stdout keeps the effects row and the landed record.
A retained row names its action and its reason code.
A retained row whose worktree path is not line safe names its assignment pointer instead of its path.

The cleanup reports `complete` when the apply returns no error, whatever the plan retained.
A failed refresh starts no cleanup, so the row reads `pending` and no checkout is touched.
A plan fault or an apply fault reports `failed`, `worktree=incomplete:cleanup`, and exit 3 with the existing resume command.
The resume re-plans the narrowed set and reports `complete` when it is empty, so a finished cleanup is not repeated.
This is the last ticket that touches the cleanup selector, so run the whole focused suite of the worktree package.
The system-suite land-race proof reads the landing stdout, and it runs under `bench test --check system`, which pins `BENCH_KIT` and `BENCH_RUN_BINARY` to the worktree.

`internal/worktree/worktree.go` is over the line budget, so change its two call sites in place and add no line there.
The five command registries are named for closure only, and this ticket does not edit them.

Line: gpt-5.6-terra / medium, three implementation iterations.
Self-probe an omission of the destination-base proof and report the observed red on the prior-landed case.
The coordinator independently swaps the retained row's reason code at another site.
