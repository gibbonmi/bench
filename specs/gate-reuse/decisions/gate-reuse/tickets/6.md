# What does the pre-code measurement count, and which result changes the scope?

Blocked by: #3, #4
Type: Grill

### Question

The criterion `FT314-gate-reuse.premise` requires a measurement of the key's saving on checkpoint-then-landing compositions and retries before any code change.
The gate run log records the root, the mode, each phase, and the elapsed time of a run, but no tree.
Decide the window, the source of each compared tree, the count, and the result that stops or narrows the build.

### Answer

The window is `main` from 2026-10-01 to the day of the run.
The first count is each spec landing whose pre-landing `main` commit is an ancestor of its source tip.
Such a composition reproduces the tree that the complete checkpoint graded.
The second count is each landing retry that ran a second whole gate on an unchanged composition.
That count comes from the session records that the friction census read.

Each saved run takes the median whole-gate wall time of the retained gate run logs.
The measurement assumes that the checkpoint and the landing had equal running executables, and it reports the result as an upper bound.
Ticket #11 takes the result. No preset number stops the build.
