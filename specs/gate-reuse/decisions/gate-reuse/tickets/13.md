# How does the complete checkpoint run under the landing broker?

Blocked by: #11
Type: Grill

### Question

Ticket #11 runs the complete checkpoint under the authenticated landing broker, but it does not name the seam.
`internal/brokermanifest` reads and digests the primary checkout's broker manifest, and `checkCandidate` compares the running executable with it.
`checkCandidate` skips a repository that declares no Bench build inputs.
Decide the seam that puts the complete checkpoint under the broker.

### Answer

In a repository that declares Bench build inputs, the complete checkpoint compares the digest of its running executable with the primary checkout's broker manifest.
It reads the manifest and digests the executable through `internal/brokermanifest`, as `checkCandidate` does.

When the two digests are equal, the checkpoint runs in its own process.
When they differ, it execs the manifest's broker with the same arguments and the same working directory.
When the manifest does not read, or the broker's digest differs from the manifest, the checkpoint refuses with a named face and runs no gate.

A repository that declares no Bench build inputs keeps the wrapper's selection, and its checkpoint green answers the landing only under an equal running executable.
The wrapper script does not change.
