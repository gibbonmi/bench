# How does the grade key get the run binary member before the lookup?

Blocked by: #3
Type: Grill

### Question

Ticket #3 puts the run binary digest in the grade key.
The lookup runs before the gate selects the run binary, and a build takes about 1.1 s at the median of 19 retained runs.
The run binary's seal binds a source digest, and the selection proves the built binary against that digest.
Decide how the key gets the run binary member.

### Answer

The run binary member is the source digest that the run binary's seal binds.
It is `freshness.Digest` over the source root that `runBinarySource` names, and the subject build computes it before the lookup, with no build.
The selection still proves the built binary against that digest before any phase runs.

In the kit, the member follows the graded tree. In a linked repository, it follows the kit that supplies the run binary.
A run whose source root declares no build inputs frames one stable value.
