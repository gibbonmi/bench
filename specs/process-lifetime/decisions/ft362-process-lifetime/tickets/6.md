# Can one owner bound every current stream shape?

Blocked by: none
Type: Prototype

### Question

Can the proposed owner bound shutdown without losing stream or artifact ownership?

The Go 1.25.14 exec implementation separates child wait from stream-copy completion.
CommandContext cancellation targets the direct process by default.
WaitDelay also addresses inherited pipes.
StdoutPipe consumers impose a separate read-before-Wait constraint.
Source: https://raw.githubusercontent.com/golang/go/go1.25.14/src/os/exec/exec.go, read on 2026-10-06.

Run a disposable probe before the spec fixes the interface.
Cover captured buffers, direct files, caller writers, and testreport's decoder.
Include a resistant child and a descendant that retains a pipe.
Include cancellation during startup and a failed group-absence probe.

The probe must report the following evidence:

- The caller returns within the selected shutdown deadline.
- One waiter owns each successful start.
- Complete normal output remains intact.
- Truncated output yields failure.
- Incomplete cleanup retains the affected artifacts.
- A blocked caller writer cannot hold cleanup authority without an explicit recovery route.
- Linux and macOS requirements remain distinct and testable.

Do not claim bounded arbitrary user-supplied I/O from a timer alone.
If the probe needs an owned stream adapter, record that responsibility explicitly.
No production migration or benchmark belongs to this ticket.

### Answer

Yes, with the stream and resource rules below.
The reviewer delegated this architecture judgment to the coordinator.
The disposable probe settles the stream strategy, not production artifact safety.
Its observed results and limits are in [the evidence asset](../assets/prototype-evidence.md).

The owner serializes start publication and cancellation requests.
One waiter owns each successful start.
Child, cancellation, stream, and cleanup results remain distinct.
The owner reads mutable process and output state only after the relevant worker finishes.

An owned pipe separates the child waiter from the output decoder.
Do not call Wait before the existing StdoutPipe reader finishes.
The replacement adapter owns its pipe closure and consumer result.
Forced closure, truncated output, or a pending external writer yields an incomplete failure.
An arbitrary blocked writer has no bounded whole-CLI reporting guarantee.

Keep each caller's existing grace and normal-exit policy.
Use a two-second grace where no finite grace exists, followed by a three-second final cleanup window.
These values are policy choices, not measured minima.
The bounds package owns durations and passes them into subprocess without an import cycle.
Preserve the worktree exec normal-output WaitDelay separately.
Preserve Linux Pdeathsig and the distinct Darwin group policy.

Each resource owner publishes durable protection before a child can use its resource.
A failed publication prevents launch.
Only proven completion of every applicable resource user permits normal release.
Incomplete cleanup retains the protection and refuses publication or successful cleanup.
An unresolved startup interval retains an unknown identity and can require indefinite retention.

The cache owner acquires its shared lock before it publishes the protection and launches a child.
It clears the protection before releasing the ordinary completed hold.
The cleaner reads protections while it holds its exclusive lock.
An unreadable or unresolved protection refuses the clean.
A process-owned lock or an in-memory completion handle supplies no protection after CLI exit.

The prospective bundle protects both direct Close and the recovery sweep.
Reuse its strict record reader, repository binding, and atomic publication owner.
Owner death alone cannot prove descendant absence.
A record without sufficient cleanup proof retains the bundle, including an ambiguous legacy record.
The future spec reconciles this posture with ADR0019's retained-descendant exception.

Protection crosses nested CLI boundaries and covers concurrent users of each enclosing resource.
An outer caller cannot infer safe release from a child's exit code or its own group absence.
Gate, lane, private binary, and private test-directory owners must consume the same unresolved disposition.
Shift recovery must retain protected scratch and worktrees even when their ordinary dirty check is empty.
The requirement covers recovery paths as well as deferred teardown.

Recovery validates the resource owner and requires positive group-absence evidence for every known user.
Age and a stale owner PID supply no removal authority.
Recovery never signals a process from a stale record.
An uncertain or unknown user keeps the resource protected.

An independent Sol 6.1/xhigh design review accepted these constraints for specification at confidence 9.
The coordinator adopts that recommendation under the reviewer's delegated judgment.
No further prototype is required before spec authoring.

Implementation must still prove these scenarios through real resource owners:

- A second process refuses cleanup after the initiating CLI returns incomplete failure.
- A nested CLI exits while a separately grouped child remains unresolved.
- Failed protection persistence prevents the child from starting.
- Cancellation reaches a resistant child during the actual shift startup race.
- Ordinary completed runs remove their protections and release their resources.
- Native Linux and macOS preserve their distinct process contracts.

The prototype supplied no production retention proof or performance measurement.
Record schemas, propagation interfaces, and recovery APIs belong in the specification.
