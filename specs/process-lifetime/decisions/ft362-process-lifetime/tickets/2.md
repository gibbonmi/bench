# Who owns lifetime mechanics?

Blocked by: none
Type: Grill

### Question

Which responsibilities move to the shared owner?

### Answer

The reviewer selected shared mechanics and caller policies.
Use `internal/subprocess` for process-group start, cancellation, escalation, wait ownership, and final cleanup observation.

Each caller retains its command, environment, output interpretation, exit-code policy, and artifact policy.
The owner returns facts that distinguish child failure, cancellation, and incomplete cleanup.
A successful child exit cannot erase a cleanup failure.

Keep `internal/bounds` as the duration policy owner.
Pass selected durations into subprocess.
The subprocess owner must not import bounds when the bounds runner imports subprocess.
This direction avoids a dependency cycle and a second duration registry.

The owner must serialize startup and cancellation.
One owner performs Wait exactly once for each successful Start.
Callers must not race an unpublished process handle.

Deleting this owner must restore substantial lifetime mechanics across the sites in ticket 1.
A wrapper that only calls Start does not meet the objective.
