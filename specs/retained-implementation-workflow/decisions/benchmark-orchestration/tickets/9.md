# What evidence permits a later default change?

Blocked by: #2
Type: Grill

### Question

The implementation default is settled by #2. What evidence permits a subsequent change to that default?

### Answer

A later default change requires repeated comparisons on tasks outside the FT311 authoring benchmark. Use equivalent acceptance and review requirements. Require preserved quality and a demonstrated cost or elapsed-time benefit.

Measure the complete accepted-change cost. Include implementation, reviews, repairs, failed attempts, and verification. Separate cached input, uncached input, and output tokens. Keep estimated cost separate from actual charges, and preserve missing data as unknown.

Report elapsed time separately from cost and quality. Default adoption remains a reviewer decision. Ticket #11 owns the assessment record and trial policy.

Reviewer confirmed this decision in the shaping conversation.
