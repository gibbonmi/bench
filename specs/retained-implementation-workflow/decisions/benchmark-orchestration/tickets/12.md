# How are implementation chunks defined and reviewed?

Blocked by: #2
Type: Grill

### Question

How are implementation chunks defined and reviewed?

### Answer

The spec author defines implementation chunks during spec authoring. Each chunk has a concrete outcome, acceptance criteria, and tests. Choose the smallest coherent behavior that can be verified and warrants a review cycle. Do not split solely by file or function. Do not separate tests and implementation into different review chunks.

The implementation session completes one chunk. Review subagents assess it against the whole spec, with their review focused on that chunk's changes. The implementation session addresses the findings before it starts the next chunk. Ticket #2 owns the session and delegation policy.

After the last chunk, the implementation session runs the overall acceptance and integration checks. It checks the completed work against every spec requirement. Another full delegated review at spec completion is not required by default. Additional review is warranted when later changes invalidate an earlier review or reveal a concern that spans chunks.

Model and effort selection remain separate decisions. Explicit reviewer instructions can override this default.

Reviewer confirmed this decision in the shaping conversation.
