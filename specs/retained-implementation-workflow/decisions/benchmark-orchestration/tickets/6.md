# What changes after repeated failure to advance?

Blocked by: #3
Type: Grill

### Question

What changes after repeated failure to advance?

### Answer

After two complete implementation-and-verification attempts produce neither progress nor useful new evidence, reassess the approach. Name a changed hypothesis and the next check that can distinguish it. Individual tool calls and expected failing TDD tests do not count as failed attempts.

The retained implementation session can use `$bench-debug` and adjust effort. It can also ask an available higher-tier model for focused diagnostic advice. This consultation has standing approval, including consultation with the top tier.

Keep the consultation small and quick, like one chat exchange. Supply the concrete question, relevant error, minimal source context, and attempted hypotheses. Request a short diagnosis and next check. The helper has no implementation or repair assignment.

The original session evaluates the advice and performs all implementation and repairs. A change of implementation model or a replacement implementation session still requires reviewer direction. Ticket #3 owns the other stop conditions.

Reviewer confirmed this decision in the shaping conversation.
