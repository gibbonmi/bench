# Who recommends the implementation line, and what line do reviews use?

Blocked by: #2, #12
Type: Grill

### Question

Who recommends the implementation line, and what line do reviews use?

### Answer

The spec author recommends one model tier and starting effort for the retained implementation session. Give a short reason based on the hardest material chunk, spec precision, uncertainty, and test coverage. Identify chunks that are likely to need more reasoning. Effort remains adjustable within the retained session. The recommendation does not authorize silent model changes.

Standards, Spec, and Coverage reviews each default to the mid tier with high effort. Each chunk receives a fresh review subagent for each axis. The spec author can recommend an exception with a reason. Explicit reviewer instructions can override these defaults.

The GPT top tier is Astra, resolved as `gpt-6-astra` for Codex. The GPT mid tier is Sol, resolved as `gpt-5.6-sol` for Codex. The GPT low tier is Terra, resolved as `gpt-5.6-terra` for Codex. Bench calls this tier `cheap`. Thus the default GPT review line is `gpt-5.6-sol` with high effort.

Use one canonical owner for the review line when implementing the shared workflow. Specs reference that policy. Measure review quality and cost to assess this starting default.

Reviewer confirmed this decision in the shaping conversation.
