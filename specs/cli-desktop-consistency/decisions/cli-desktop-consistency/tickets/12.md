# Evidence-backed guarantees

Blocked by: #11
Type: Grill

### Question

Which support and recovery guarantees does the evidence justify?

Review [Supported integration routes](11.md) and its compatibility evidence.
Resolve any remaining required-capability boundaries, unavailable recovery routes, and version-change behavior.
Preserve the decisions already closed in this map.
Surface any material conflict with the approved outcome for the reviewer.
Obtain the reviewer's confirmation of shared understanding before the map becomes ready.

### Answer

The reviewer confirms the complete shaped outcome and all three evidence-backed recommendations.

Compatibility depends on verified required capabilities in each active interface.
Identical CLI and desktop runtime version numbers are not required.
A relevant runtime, configuration, or workspace change invalidates the affected evidence.
Bench must repeat the affected checks before it reports current compatibility.

When a required tool fails before Bench starts, recovery guidance remains accessible outside that failed tool path.
The guidance identifies the affected work and a supported recovery route when one is known.
An upstream failure without a supported repair remains explicitly unresolved.
Bench reports recovery only after the actual failed interface passes the required retest with its normal permissions.
[Repair authority](8.md) continues to govern automatic and manual recovery.

A desktop-specific tool is required when a Bench operation needs it and no verified equivalent route provides the same outcome.
An unavailable optional tool does not block unrelated Bench work.
An unavailable required capability blocks its affected operation under [Capability failure](7.md).
