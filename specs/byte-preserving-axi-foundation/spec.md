# Byte-preserving AXI foundation

Status: staged

Decision source: `specs/byte-preserving-axi-foundation/decisions/ft173-axi-contract.md`

## Problem

Bench publishes a ten-principle Agent eXperience Interface contract, but the kit documents only seven principles and implements the contract through strong local owners rather than one declared system. Flat TOON bytes and common argv grammar are shared; outcome kinds, executable actions, bounded projections, aggregate facts, empty-state meaning, command membership, and renderer composition remain independently represented.

That fragmentation makes later AXI migrations unsafe. A universal helper could silently flatten distinct truncation units, turn unknown totals into zero, normalize semantically different empty states, move errors between streams, widen accepted argv, or render contextual actions before their compatibility review. The foundation must create reusable typed mechanics while keeping every current public observation byte-for-byte unchanged.

## Solution

Introduce one internal AXI package that owns typed outcome, action, bounded-projection, aggregate, surface-declaration, and registry mechanics. Existing command domains continue to own semantic facts and existing renderers continue to own public bytes; they consume the shared carriers instead of re-deriving their structure. The production registry declares current AXI membership and internal metadata from the same entries that execute commands.

Expand the project AXI guidance to state all ten published principles and Bench's approved per-surface application of them. Route the four existing truncation policies and the existing outcome, action, aggregate, and empty-state families through the shared mechanics without normalizing their meanings. A focused compatibility harness compares the complete baseline and candidate argv matrix and requires exact stdout, stderr, exit, accepted/rejected argv, empty-state, and default/`--full` equality. This spec emits no `help[]`, adds no flag or schema version, and changes no public output.

## User stories

1. As a kit contributor, I want one complete ten-principle AXI contract and one registry-derived declaration of the surfaces that currently implement it, so future commands cannot invent a second contract or disappear from the inventory. Line: gpt-5.6-sol / high. This story changes generation-guiding kit prose, so the profile's leverage override applies even though the registry mechanics are gate-observable.
2. As an agent running an existing Bench command, I want success, no-op, empty, refusal, usage, specialized domain outcomes, and next-action facts to travel through shared typed carriers while the current renderer returns exactly the same bytes, stream, and exit, so internal consolidation does not alter the command I consume. Line: gpt-5.6-terra / high. The seam is known, but semantic distinctions across status, shift, lifecycle, publication, and cleanup need high-effort compatibility work.
3. As an agent reading bounded Bench output, I want every current truncation owner to use one parameterized projection mechanic while retaining its existing cap, counting unit, metadata, safety posture, and default/`--full` behavior, so the foundation removes duplicated mechanics without double-truncating or weakening authority-bearing scans. Line: gpt-5.6-terra / high. Four policies share mechanics but not meaning, and the work crosses several ownership fences.
4. As an agent reading counts and empty results, I want shared aggregate and empty-state carriers to serialize facts supplied by the current semantic owners without inferring totals, completeness, or absence, so complete, partial, unknown, zero-class, one-row empty, zero-row empty, and prose-clean results remain exact. Line: gpt-5.6-terra / high. A wrong generic derivation can remain syntactically valid while changing meaning, so the weakly observable semantics require the mid/high line.
5. As a contributor reviewing the migration, I want one executable compatibility matrix over every affected command family and argv class, so any change to stdout, stderr, exits, accepted argv, empty states, or default/`--full` behavior fails before promotion. Line: gpt-5.6-terra / high. The matrix is broad and exact-byte correctness is the acceptance seam.

## Implementation decisions

- `internal/axi` is the one shared owner. It exposes small typed carriers and validation/composition mechanics; it does not own command-domain semantics or replace `internal/toon`, `internal/usage`, `internal/sanitize`, or existing domain renderers. Deleting the package would redistribute carrier validation and registry rules across consumers, so the module is deep rather than a pass-through.
- An outcome is generic over a domain-owned kind and records that kind, its owner-supplied exit policy, typed domain payload, ordered aggregates, and zero or more typed actions. AXI query domains retain success, no-op, empty, refusal, and usage with their established 0/1/2 taxonomy. Operational domains retain their separately reviewed kinds and exits: in particular, `shift.Outcome` remains the one owner of `complete`, `failed`, `usage`, `incomplete`, `no-op`, and `interrupted` and exits `0`, `1`, `2`, `3`, `4`, and `130`. The shared carrier validates against the supplied domain policy rather than defining a second universal mapping. Existing renderers map the typed value to their current bytes; the foundation adds no public envelope.
- An action is an internal executable template with literal command tokens, fixed arguments already known to the domain, and explicitly open placeholders. It distinguishes invokable commands from orchestration prose. Existing `action`, `next`, `next_action`, and hint bytes remain where they are and remain exact; no action is emitted as `help[]` in this spec.
- A bounded projection carries already-selected content plus owner-supplied total, emitted, omitted, truncated, completeness, and counting-unit facts. Its policy is parameterized and cannot infer semantic totals. The four current owners retain these exact policies: `sanitize.Preview` caps 120 Unicode code points and reports original bytes; roadmap context caps 4096 UTF-8-safe bytes and becomes uncapped under `--full`; worktree ignored inventory retains its safety/fingerprint enumeration and applies only the final 20/1000 visible-entry projection through the shared mechanic; outline retains the 200-row default, all rows under `--full`, and owner-derived skip/total/omitted meaning.
- An aggregate is an ordered typed fact supplied by its semantic owner. It represents known numeric values, explicit unknown values, booleans, and zero-valued disposition classes without coercion. Renderers retain current field names, field order, block order, and string-versus-number types. The aggregate carrier never derives total from visible rows or completeness from exit 0.
- Empty is an outcome kind, not a universal rendering. Existing zero-row TOON tables, spec-build's one-row `state=empty` plus its `--full` zero-row detail blocks, human prose clean states, and absent/unreadable refusals remain distinct and byte-exact.
- The production command registry is enriched with internal AXI declarations and is the executable membership source. It declares all 48 current root entries, attachment disposition, current AXI surface membership, grammar/help owner where one exists, renderer family, empty-state class, and default/detail mode availability. Nested family registries compose the same declaration type. Metadata is validated but not emitted, and it cannot make an undeclared operational command AXI-conformant by default.
- The exact currently AXI-declared set is `anchors`, `learnings`, `maps`, `guards`, `diff`, `coverage`, and nested `worktree list`. Every other root or nested operation retains its separately reviewed operational, system, ship, or plumbing contract. The registry is the production source for that disposition; an independent conformance expectation enumerates the seven approved members so flipping either a query member or an operational exemption is red. `bench spec build` remains operational until its downstream full-AXI migration lands.
- The complete ten-principle contract is:
  1. **Token-efficient output:** declared AXI surfaces use the existing TOON output seam; internal logic remains typed.
  2. **Minimal default schemas:** declarations describe the current default/detail schemas; this foundation neither adds `--fields` nor changes a schema.
  3. **Content truncation:** bounded content retains a size/completeness fact and the current escape hatch; a value already bounded by its domain is not truncated again.
  4. **Pre-computed aggregates:** domains supply totals and derived status so renderers do not force another query or infer facts from a page.
  5. **Definitive empty states:** successful absence is explicit and distinguishable from unreadable, unknown, and failed state.
  6. **Structured errors and honest exit codes:** AXI surfaces use structured stdout errors, no prompts, idempotent no-op/0, unsatisfied intent/1, and usage/2; surfaces with a separately reviewed sink contract keep it until their migration.
  7. **Ambient context:** explicit setup installs the existing directory-scoped session dashboard, and on-demand guidance derives from the same home-view contract; this foundation changes neither hook bytes nor wiring.
  8. **Content first:** no-argument live data applies only to a surface declared for it; it never authorizes an operational mutation or changes an existing family home in this foundation.
  9. **Contextual disclosure:** typed actions carry known fixed arguments and honest placeholders; rendering `help[]` is deferred to its byte-changing downstream specs.
  10. **Consistent way to get help:** declared subcommands expose their existing concise help grammar; this foundation records but does not add accepted help spellings.
- The compatibility harness is an independently authored expectation, permitted by the project's test-expectation exception because deleting or mutating a public observation must make it red. It records a frozen baseline manifest from the pinned source and executes the candidate through the production `Command` seam or exact selected executable where stream, wrapper, or process identity is observable. Each case compares stdout and stderr as raw bytes, exit status, and whether argv is accepted or rejected; it never derives expected bytes by running the candidate renderer.
- The baseline manifest records subject `974020e4af8de5ed75098c4c5934a8907952bb2b`, the canonical-builder seal for one exact baseline executable, stable case IDs, argv, fixture identity, raw stdout and stderr bytes, exit, and accepted/rejected classification. Candidate comparison builds one exact candidate executable through the same canonical builder. A manifest reader rejects an unpinned subject, missing seal, non-regular or symlinked fixture, duplicate case ID, missing observation, and any case whose expected bytes were refreshed from the candidate.
- Manifest membership is closed over three production owners: all 48 Go root registry entries; wrapper no-argument/help, public `--version` and `-v` aliases, and wrapper-only `repair`; and the declared nested grammars—eight worktree modes, three ordinary spec operations, nine spec-build operations, five release operations, two release-preflight modes, two gate-go modes, one gate `pin` operation, and two worktree-hook modes. Every member declares each applicable argv equivalence class or an exact not-applicable reason. Required classes are root-dispatcher zero argv, wrapper no-argument/help, wrapper version aliases, family no-operation/missing operation, unknown root subcommand, unknown nested operation, default success, defined no-op, empty, refusal, outside-repo, long help, short help, bare help, unknown flag, repeated flag, missing flag value, empty required flag value, `--`, missing positional, empty positional, excess positional, and `--full`; a missing, duplicate, or unclassified member/class is red. Every pre-existing command output or grammar fixture maps to exactly one stable manifest case ID so the harness cannot replace the existing fixture inventory with a sample.
- The argv matrix covers zero/one/many TOON rows; typed and numeric-looking cells; quoting, newline, tab, return, ESC, BEL, backslash, and final newline behavior; success, defined no-op, help spellings, unknown/repeated/missing flags, missing/empty/excess positionals, `--`, outside-repo state, and lifecycle refusal; every current default/`--full` pair; each distinct empty-state rendering; all four bounds policies below/at/above their caps and at multibyte boundaries; complete, partial, unknown, zero-class, skipped, and emitted-less-than-total aggregates; and existing action/next/hint strings.
- This is a wide refactor under `craft-tickets`. Expansion introduces and proves the shared types and registry validation beside existing owners. Migrations then move one independently green domain family at a time. Contraction removes the superseded derivations only after every affected family is on the shared mechanics and the compatibility matrix remains exact.

## Testing decisions

- TDD attaches first at the pure `internal/axi` interface. Each carrier test starts from minimal declarations and asserts exact validation, ordering, unknown/zero distinction, fixed/open action arguments, and policy-parameterized projection behavior before production call sites move.
- Existing renderer tests remain the command-domain oracle. Migration tests drive the same domain values through the shared carriers and existing renderer, then require their pre-migration literals exactly; they do not mock internal collaborators or recompute expectations with the candidate helper.
- The compatibility matrix attaches at the highest production command seam that still observes the contract. In-process `Command` cases cover ordinary commands; an exact selected executable is used only for wrapper routing, stdout/stderr separation, environment, signals, teardown, or installed/stripped behavior.
- Registry tests enumerate all 48 root entries and every nested family member from production declarations. They reject missing, duplicate, or independently advertised members and prove metadata is inert by comparing public output before and after declaration changes.
- Each truncation owner retains its focused mutation tests. Independent mutations change its cap, unit, total, UTF-8 boundary, default/`--full` branch, omitted count, or worktree safety/fingerprint input; a generic projection golden cannot substitute for those owner probes.
- Aggregate and empty-state tests mutate owner-supplied facts rather than renderer assertions: total becomes visible-row count, unknown becomes zero, partial becomes complete, a zero disposition disappears, a one-row empty becomes a zero table, or absent state becomes empty. Each must fail at the responsible owner or compatibility case.
- The dev gate observes the completed foundation through ordinary Go tests and registry-derived conformance. Ticket-local checks run only their affected package and declared conformance/canary owner; the sole whole-project gate belongs to spec-build promotion.

### Degenerate implementations the map rejects

- Add empty shared structs while leaving every caller on local derivations. AX3, OC3–OC5, BD2–BD5, AG3–AG5, and EM2 require production declarations and per-member call sites to reach the shared mechanics.
- Wrap all four truncation owners around `sanitize.Preview`. BD3–BD5 fail on byte units, full behavior, semantic totals, and authority-bearing worktree state.
- Infer every aggregate from displayed rows. AG2 fails on unknown guard totals, skipped outline inputs, and explicit zero reclamation classes.
- Normalize every empty result to a zero-row table. EM1 fails on spec-build and prose-clean bytes.
- Capture candidate output as the expected baseline. CP1 requires an independently frozen manifest from the pinned source, and mutation tests alter the subject rather than the assertion.
- Classify every registry member as AXI or non-AXI without preserving the approved set. AX4 flips one member in each direction and requires both mutations to fail.
- Preserve stdout but widen argv or move an error to stderr. CP1, CP2, and CP4 compare acceptance, both streams, and exit independently.
- Render typed actions immediately as `help[]`. OC2 and CP4 require zero new emitters and exact existing bytes.

### Edge inventory

- Error path — CP1 and CP2 cover structured query errors, direct/system stderr contracts, lifecycle refusal, render failure, and 0/1/2 exits; outcome validation refuses impossible kind/exit pairs.
- Empty or absent input — EM1 distinguishes zero-row, one-row empty, prose clean, absent source, unreadable source, unknown count, empty positional, and no-argument behavior.
- Boundary values — BD2–BD5 cover below, exactly at, and above every current cap; multibyte cut points; zero/one/many rows; 20/1000 worktree entries; 200 outline rows; and emitted less than total.
- Malformed input — CP2 and CP5 cover unknown/repeated/missing flags, missing/empty/excess positionals, `--`, invalid controls, and malformed baseline entries; the harness fails closed on an unpinned subject, missing seal, non-regular, symlinked, duplicate, incomplete, or unclassified fixture/member/case.
- Interrupted or partial state — AG2 retains partial and unknown aggregate facts; worktree stat races and unsafe entries remain refusals rather than truncated success. The foundation introduces no new long-running process owner.
- Re-run idempotency — each compatibility case is run twice and must return the same observations; existing mutation no-ops retain exit 0 and exact bytes.
- Process-boundary lifecycle — cases that require an executable start a fresh selected process for baseline and candidate observations; no process-local value is reused as proof of serialized behavior.
- Hostile environment — the matrix covers repository and temporary paths with spaces/glob characters, deep cwd, stripped PATH where currently supported, symlink invocation, missing optional tools, and control-bearing Git text according to each existing sink's policy.
- Command self-observation — registry metadata and compatibility fixtures are read-only internal inputs; no command changes a fact it reports during the comparison.
- Special files and dangling symlinks — baseline manifests and discovered fixture paths must be regular files and are rejected before reading, so the harness cannot block or reinterpret a broken link as empty.

### Won't handle

- Adding an AXI `--fields` option — this changes accepted argv and schemas; it belongs to a separately reviewed output migration.
- Making every operational command content-first or changing a family no-argument result — AXI attaches per surface, and this foundation has no public-output exception.
- Emitting `help[]` from the new action carrier — contextual disclosure is intentionally downstream after stable schemas.
- Replacing owner-specific semantic facts with one universal renderer — shared carriers move mechanics, not authority.
