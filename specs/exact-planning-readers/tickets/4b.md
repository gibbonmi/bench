## What to build

Deliver `bench worktree list --spec <slug-or-path>` through a commitment-owned `RunScopes(state, assignmentID)` projection and `tickets.Covers`.
Read Assignments and Commitment once from the same intent ledger; never infer a relation from a label, a branch, or a spec file's presence.
Build one deterministic related projection through the existing row, fact, ordered-action, and AXI owners, with matched and unbound counts.
That projection supplies both the page identity and the paged content, and every continuation recomputes it before output.

`--spec` refuses with the selected-view and repeated-target forms.
The default and selected list views keep their bytes, including their testdata pins.
Keep the SKILL.md sentence that the retained-workflow anchor requires; append to that row only.
Expose RunScopes beside runScope, or move both into run_scope.go when growth requires it.
System verification requires BENCH_KIT and the sealed run binary that `bench test --check system` supplies.

## Acceptance

- [ ] Related results use actual binding and continuation scopes, assignment-ID order, and explicit matched and unbound counts.
- [ ] Navigation actions use existing observed state and authorization; the page identity grants no execution authority.
- [ ] A nonterminal related page refuses before content when assignments, rendered fields, tree presence, leases, landedness, ignored files, counts, or actions change while commitment data stays equal.
- [ ] Planned TestRelatedWorktreeFilter, TestRelatedContinuationRefusesChangedProjection, and the system witness grade these predicates.
- [ ] Default and selected list views keep their existing bytes and refusals.
