## What to build

Every production command member — the 48 roots in `commandRegistry` and the 33 nested members —
carries one explicit empty disposition: either a named class from the shared enum, which a real
invocation must reach, or an explicit no-semantic-empty declaration. The nested members are the
seven `usage.worktreeCommands` entries plus the default `bench worktree [--refresh] [objective...]`
subshell surface (8); `spec` implemented/retire/history, the `spec build` family home, and the nine
`buildOperationOrder` operations (13); the five `release` publication operations (5); the two
`release-preflight` modes `--mode verify` and `--mode publish` (2); the one nested `gate pin`
operation (1); the two `gate-go` steps `gofmt` and `test` (2); and the `worktree-hook` `create`
branch plus its default `remove` branch (2). Metadata may not invent empty behavior, and a member
whose disposition is left at its zero value is refused rather than read as no-semantic-empty.

The check is registry-derived: `internal/conformance` enumerates the production members
themselves rather than a parallel catalog, drives each empty-capable member's real entry in
a `t.TempDir()` fixture repository under a per-member deadline, and compares the class
reached to the class declared. `projects/benchkit.md` restates the conforming AXI surface,
so it is on this ticket's fence — the declaration and its advertisement move together.

The nested member lists come from the packages that own each dispatch — `internal/usage`,
`internal/spec`, `internal/publication`, `internal/preflight`, `internal/gate`, and
`internal/harness` — which the prerequisite `axi-carriers-and-registry` build already exports
for its own declaration records. Those packages sit outside this spec's approved fences, so
this ticket reads them and writes none of them. If a nested family turns out to have no
exported list to read, stop and report the exact path for reviewed scope repair; never widen
the fence locally.

Tree condition that must hold when this ticket is refreshed: `internal/axi/empty.go` exists
and declares the exported empty classification type `EmptyClass` with its distinct class
constants and an explicit no-semantic-empty value, `cmd/bench/command_registry.go`
carries a per-member disposition field, and each nested owner package exports the member list
its declaration records already consume. If any of those is absent, stop and report rather
than build — the prerequisite `axi-carriers-and-registry` build has not landed.
