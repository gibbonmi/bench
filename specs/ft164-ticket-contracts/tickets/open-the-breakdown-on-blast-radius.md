## What to build

FT164 story 3: the numbered breakdown method invokes the classification that
already sits beside it, so a wide refactor is sequenced rather than sliced into
one over-wide tracer that exhausts a delegate's context.

Step 1 of the method opens on the blast-radius branch: a wide refactor takes
expand–migrate–contract, each migration sized by exactly one ownership fence,
and the contract ticket's `Blocked by:` names every migration so no contract
runs while a migration is open. Step 2's "confirm independently green" gains a
mechanical method — fence disjointness decides concurrent eligibility, which is
a correctness precondition once tickets are assigned in parallel, not a
drafting guess. The one-line test-harness ceiling lands beside that same step 2
rule, inside `## Draft the breakdown` so its needle has an owning section to
scope to: a one-line change does not buy a worktree, a fresh delegate, and a
full gate by default.

The cadence paragraph gains the evidence-authorship sentence: a ticket that
changes gate cadence names which command authors gate evidence — `bench gate`,
the canonical producing entry — and which phase consumes it, because a bare
`gate-run --fresh` prints a valid phase result without publishing the
project-green evidence promotion consumes.

Enforcement is anchor-first in the same diff: six needles scoped to the sections
that own them, each with one byte-exact mutation-table row proving its diagnostic
fires.
Ordinal position inside a section is not anchor-expressible, so that the branch
is the *opening* step is review-graded and stated as such.
