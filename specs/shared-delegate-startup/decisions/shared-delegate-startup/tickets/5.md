# How should spec authorship join the optional workflow?

Blocked by: #1
Type: Grill

### Question

How should the invoking agent choose between one author and sequential spec and ticket authors?

Keep the existing approved-context fork as the default author for both artifacts.
Permit a separate ticket fork when design and ticket work are substantial distinct jobs.

### Answer

Preserve the existing approved-context spec-author fork and its inherited line.
By default, that author writes the spec and its tickets.
The invoking agent may select a sequential ticket fork when design and ticket work are substantial distinct jobs.
It states its reason without another user permission step.
Neither route adds a preparation session.

The second fork starts after the first author returns the completed spec and stops writing.
It receives the completed spec and approved source, inherits the invoking line, and uses the existing assignment isolation.
One independent review covers the completed spec and ticket pair.
The cost estimate includes both authors, preparation, output, and expected repairs.

If the second fork is unsuitable or unavailable, report the fallback and resume the original author for tickets.
The optional route does not relax the mandatory initial fork or its capable-session handoff.
No automatic compaction, launcher, or CLI change joins this option.
