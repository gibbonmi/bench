## What to build

Move the layer capture out of the cleanup's recovery function into one shared function in a new file of the worktree package.
The function takes the root, the worktree path, one flag, and one optional tip.
The flag keeps the working layer even when it equals the head tree.
It returns the manifest root commit, the payload commits, and the base head, and it writes no ref and no ledger record.

When the tip is set and differs from the head, the manifest records it in a `tip` field.
The root commit then takes the tip as one more parent.
The cleanup's recovery function calls it with the flag off and no tip.
It keeps its ref write, its ledger write, its fault step, and its verification as they are.
The existing layer-preservation test is the differential, and it must pass unchanged.

Add the reset namespace to the ledger package beside the recovery namespace.
The namespace is `refs/bench/reset/`, and its prefix function takes the owner id and the assignment id, exactly as the recovery prefix does.
Export both through the intent aliases file.
Write no validation rule over the new namespace, because the assignment record never names a reset ref.

Give the session-start reconcile one more rule.
A ref under the reset namespace whose owner and assignment segments match no ledger record is deleted against the object the listing read.
A reset ref whose segments match any record survives, whatever the record's state.
The rule reads the ledger once, and an unreadable ledger deletes no reset ref.
Do not add the reset namespace to the lifecycle namespace list, because that list is emptied whole.
Report the deleted reset refs inside the existing swept count.

The five command registries are named for closure only, and this ticket does not edit them.

Line: gpt-5.6-terra / medium, two implementation iterations.
Self-probe an omission of the record match in the new sweep rule and report the observed red on the active-assignment case.
The coordinator independently omits the working-layer flag at another site.
