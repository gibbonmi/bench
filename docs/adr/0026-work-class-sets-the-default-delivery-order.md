# Work class sets the default delivery order

Each roadmap row has one class by its purpose: fix, refactor, feature, or
decision-only. A fix corrects a confirmed defect in existing behavior. A
refactor changes structure and keeps behavior. A feature adds a capability or
guidance.

When the reviewer orders a milestone, confirmed defects come first by
default, then refactoring, then new features. Modernization and deepening work
are the current priority inside that order. An explicit reviewer order for a
milestone governs over this default.

The class informs a commitment proposal. It never reorders work that the
reviewer has already committed.

A routine roadmap drain never displaces committed work, and it never admits
new work into the commitment. An existing recommended sequence never becomes
an approved commitment automatically. Each change to the commitment needs an
explicit reviewer approval of that exact change.
