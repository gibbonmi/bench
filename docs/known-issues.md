# Known issues

This file is the one owner of the known issues in this repository and their workarounds.
A coordinator reads it before it writes a delegate charge, and a delegate reads it during its work.
Each row names a retire condition: an obligation in the body of the owning roadmap row, or "no owner".
When the retire condition holds, the change that makes it hold removes the row.

| Issue | Workaround | Retire condition |
|---|---|---|
| After a ticket commit, the `dist/bench` binary of the worktree is stale, and the build preflight shows `binary-seal` red. | Run `bench worktree build <target>`. | FT406: a Go commit in a build worktree leaves no stale `dist/bench` for the next preflight. |
| An adoption writer now removes its lock file when it releases its lease. An older Bench binary does not check that the lock file path still names the file that it locked. When an older binary and a newer binary write to the same destination at the same time, both writers can hold that destination. | Use one Bench version at a time for adoption writes (Link, Setup, Upgrade, Unlink, and compatibility repair). Finish or stop each session on the older binary before you use the newer binary. | no owner: every session uses a Bench binary that is built from the adoption lock fix. |
| `bench record verification` reads each excerpt from a file. A response that Bench does not spill leaves no file. | Write the excerpt to a file first, then pass that file to `--excerpt`. | FT405: the record verb reads an excerpt from the last response of the worktree. |
| When the child of `bench worktree exec` spills, the outer response spills too. The outer spill file holds only the child's `spilled{...}` frame, not the native bytes. | Open the outer spill file, read the `path=` cell of its inner frame, and copy that inner file for `--excerpt` or `--probe-result`. | no owner: a nested bounded response reaches its native bytes in one hop. |
| A `bench record assignment` call changes the plan digest. The next `bench record chunk` then refuses with a stale plan digest. | After each assignment record, run `bench record amendment <slug> --source <HEAD>` before the chunk freeze. | no owner: an assignment-only plan change leaves the chunk freeze current. |
| In a delegated build, `bench record confirmation` refuses a test-only repair. The repair-assignment plan commit to the spec is in the delta, and the prover counts it as a non-test file. | Run a confirming round of all three axes on the test-only delta. | no owner: the test-only prover excludes the plan bytes that `bench record assignment` and `bench record amendment` write. |
| `bench preflight evidence <id> --check-current` refuses from the primary checkout, because the evidence binds an assignment worktree. | Run it as `bench worktree exec <target> -- bench preflight evidence <id> --check-current`. | no owner: each review and build charge names the exec form. |
| A spec fork can add a seam that its decision source does not name, and no research covers that seam. No check finds the unresearched seam before the spec review. | Before the spec review, cite one `path:line` and one research finding for each seam that the spec adds beyond its decision source. | no owner: a build preflight check refuses a spec seam that cites no research. |
| A spec fork can drop an anchor registry file, or its `_test.go` twin, that pins a needle in a guidance file that the spec edits. No check finds the dropped registry before the spec review. | For each guidance path that the spec edits, run `rg` across `internal/anchors` and `internal/conformance`, and name each hit, test twins included. | no owner: the build preflight writes proposal names each anchor registry file and twin that pins a needle in an edited guidance file. |
