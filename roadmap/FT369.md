**FT369 (MEDIUM) — the delegate charge and the slicing checks close the 2026-09-30 batch's fence and venue gaps.**

The 2026-09-30 light-path batch showed three guidance gaps:

- A ticket that changes a helper or deletes a path did not name every caller file and
  every tracked `capture/` reference in `Writes:`.
- Author and repair charges did not name the read and search venue. Authors ran raw
  `ls`, `cat`, and `rg` instead of the harness read tools or `bench worktree exec`.
- An author edited its own ticket after the ticket commit with no separate commit and
  no learning entry.

The slicing checks and the charge list each gain the missing rule.

The 2026-10-01 and 2026-10-02 builds add two rules. A `(new)` marker stays on a `Writes:`
path while the path is absent from the build base tree. The author of a CLI form probes
each member of each refusal step that the form joins.

A ticket that deletes or renames a Go symbol derives its caller files from
`bench consumers`. A ticket that cuts a duplicated helper also finds each copy by its
body shape. A copy under another name has no reference to resolve.

The slicing default keeps the larger ticket. A split needs a slice with its own
red-capable test and one of two triggers. The first trigger is two or more
probe-dependent fields in one ticket. The second is a new file that will likely pass its
budget. Sharper acceptance text goes on
the large ticket instead of a split. This changes the `craft-tickets` rule to split
independently useful outcomes, so it needs the reviewer's approval.
