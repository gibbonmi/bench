**FT352 (MEDIUM, decision required) — the orchestrator reads its own context size, and a spec can then restore a gated ticket fork.**

Bench cannot read the orchestrator's context size. The Codex transcript reader
maps only the total token usage, and Bench has no Claude reader. Decide the data
source for each harness, then build the reader.

After the reader exists, a spec can restore the optional ticket fork under the
reviewer's 2026-09-28 rule. A fork runs while the orchestrator's context is
under 100k tokens. At 100k tokens or more, the orchestrator spawns a fresh
delegate. The `craft-line` model-mismatch rule still applies. The fork route
changes the fresh-author rule in the shared workflow, so the spec needs the
reviewer's approval of that rule change. The retired shared-delegate-startup
amendment holds the draft rows.

FT231 owns the harness data sources for measurement, and FT204 owns the bounded
transcript query. Settle the reader's owner with those rows before a spec.

`/bench-write-spec` can also split into two forks with a checkpoint between them. A
read-only delegate first gathers a compressed inventory. The first fork writes the spec,
and a strong review and the decision consultation close it. A second fork reads the
approved spec cold and slices the tickets. A cheaper review grades the tickets, because
build preflight and `bench coverage --check` already enforce closure paths and row
mapping.

This split composes with the fork route above. It changes the one-review-round
and one-sign-off rule of the spec phase, so it needs the reviewer's decision.
