**FT354 (MEDIUM) — strict JSON, atomic replace, and shell quoting each have one owner.**

Three functions render a value as one POSIX shell token: `axi.ShellQuote`,
`sanitize.ShellQuote`, and a private `shellQuote` in `internal/freshness`.
`axi.ShellQuote` prints a safe value bare and escapes a single quote as `'"'"'`. The other
two always quote and escape a single quote as `'\''`. About 20 call sites split between
them, and a worktree build refusal quotes its label through `sanitize`. The decision names
the surviving function and its bare-token rule. A merge changes printed commands across the
kit, so each changed command line needs a test update in the same landing.

Two more primitives have several owners. A duplicate-key JSON read lives in `jsonfile`,
the gate verdict store, `reviewrecord`, and `releaseevidence`. An atomic replace lives in
five modules, and the copies disagree on the directory fsync. `jsonfile` owns the strict
read, and the gate keeps its sentinel errors through it. One replace module owns one
durability posture. These two parts need no decision, and a spec can take them after the
quoting decision.

The staged specs are `strict-json-ownership`, `durable-file-replacement`,
`durable-caller-migration`, and `shell-argument-ownership`. Each spec names the outcomes
that stay open.
