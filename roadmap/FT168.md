**FT168 (MEDIUM) — file-backed replacements and system or Markdown subjects extend the focused probe.**

The focused swap and omission probe ships as `bench probe`.
`--omit-file` reads a multiline omission from a file, and `--unwrap` removes one wrapper call.
The remaining replacement face reads multiline replacement text for `--with` from a file.
The remaining subject faces support Markdown files and registered system checks.
Named fixture and class evidence must remain producible through the registered check owner.

A system-check subject builds through the worktree build, so a system-row probe needs no manual edit, rebuild, and restore.
One probe takes `--insert-before` for an insertion and `--expect` for the expected witness.
`bench canary <fixture>` runs one canary fixture.
A `--names` form lists the failing test names and compares them with a base set, so a migration probe needs no hand diff.

FT98 owns preservation support. Each new face must restore the original subject and retain the existing deliberate-red verdict.
The full gate remains the oracle.

The probe result reports the mutated run's exit in its `probe_execution` table, and
`bench record verification --probe-result` imports a complete result.

The replacement-file and system forms stay here. Three faces join them. A
deletion form replaces the emptying `--omit-file`, a mutant compile error names itself, and
a second probe on the same file refuses.

The verdict row also names the first failing test. A swap accepts a line or occurrence
anchor, so it can target one of two identical lines. The result row can also print the
omitted or swapped text and rerun the focused green after the restore. Each probe then pins
its own mutation and needs no second `bench test` call.

Since the `probe_execution` table shipped, a biting answer has 11 lines against the
10-line response bound, so every biting answer spills. The reviewer decides between this
shape, a one-line `probe_execution` row, and a wider bound for `bench probe`.

A probe whose selected test reads no live copy of the subject says so. A swap whose old text wraps across a line names the wrap.

The canary and failing-name faces stay here. A `--occurrence <n>` anchor
and an echo of the mutation text in the response join the anchor face.
