**FT168 (MEDIUM) — the focused probe runs one canary, compares failing names, and echoes its mutation.**

`bench probe` takes swap, omission, unwrap, insertion, deletion, and mutant-set forms. It
reads replacement text from a file, takes an occurrence anchor and an expected witness, and
grades package, check, and system subjects. The verdict row names the first failing test,
and a mutant compile error names itself. `bench record verification --probe-result` imports
a complete result.

Three faces stay open. `bench canary <fixture>` runs one canary fixture. A `--names` form
lists the failing test names and compares them with a base set, so a migration probe needs
no hand diff. The result row prints the omitted or swapped text and reruns the focused green
after the restore. Each probe then pins its own mutation and needs no second `bench test` call.

A probe whose selected test reads no live copy of the subject says so. A swap whose old text
wraps across a line names the wrap.

The probe result also carries each failing line and a `witness_red` cell, so an author
parses no failure table by hand. An ambiguous `--omit` refusal lists the matching lines.

FT98 owns preservation support. Each new face must restore the original subject and retain
the existing deliberate-red verdict. The full gate remains the oracle.

`--insert-before` takes inline multi-line text, so a multi-line mutant needs no scratch
file. `--mutants` takes a `--run` selection for each mutant.

Each entry of a `bench probe --mutants` set can name its own subject file, so one witness can span two files.

Three more faces: `first_failure` names the first failure in run order, `--expect` combines with `--run`, and a ship-tier conformance subject gets a probe route. The probe route needs a reviewer decision, because `bench test` refuses that check by design.
