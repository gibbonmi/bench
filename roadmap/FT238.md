**FT238 (MEDIUM) — hygiene batch: worktree-path ergonomics, a commit dry-run, the heredoc guard gap, and a run-binary glossary term.**
Four small pieces, batched under one gate because each separately pays a full
run for a few lines.

`bench worktree path` emits a tilde-prefixed path (`~/.bench/worktrees/...`)
that no shell expands when quoted, so every caller hand-builds an absolute path
from `$HOME` instead of using the verb; emit the resolved absolute path
instead. Relatedly, no verb moves a retained worktree to a new base —
`create --refresh` refreshes the pool, not the checkout, and the path-taking
verbs reject the tilde form the path verb itself emits, so `release` cannot
substitute either; raw Git inside the worktree is the only route today,
against this repo's own preference for lifecycle through Bench verbs.

`bench commit` is the only surface that gates a composed snapshot of named
paths, and it commits on green as its whole purpose, so diagnosing which phase
a composed set reds on means either committing junk or grading a different
subject with a working-tree `go test`. `bench commit --dry-run` gates the
composed snapshot and reports the phase verdicts without committing.

The degraded git guard in `internal/gitguard` classifies a heredoc body as
command text: writing a file whose contents mention a destructive git command
is refused, because the classifier reads the whole command string rather than
recognizing a heredoc body as data the shell hands to a file. Same class FT229
fixed for the degraded rim; the core classifier still matches it.

`CONTEXT.md` has no term for the executable the gate authorizes and runs —
`internal/runbinary` calls it a Selection, and prose elsewhere calls it the run
binary, the private binary, or the selected executable. One glossary entry
picks the canonical term and retires the other two.
