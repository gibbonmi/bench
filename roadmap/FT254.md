**FT254 (MEDIUM) — `bench worktree exec` is the comfortable path for multi-step work.**

The exec help shows stdin with a heredoc example. `bench worktree show <target>
<rev>:<path>` prints the blob bytes unchanged. Every exec failure after target
resolution prints the absolute worktree path. Every earlier refusal names
`bench worktree list`.

`bench worktree exec --env KEY=VALUE` supplies worktree-local inputs. A missing
tree has no `path` or `exec` action, and both `list` and `exec` name its recovery
verb. A retained release names its reachable release form.

The follow-on guard accepts a non-Bench step before `bench worktree exec` and a
quoted `|` in the child argv. It names a refused segment and operator. Every
argument after `--` reaches the child, whose stderr and exit code pass through
unchanged. An exec grammar refusal exits 2, and its stderr starts with `usage:
bench worktree exec`.

`bench worktree exec` also receives ambient worktree-root or label-expanding
context, so callers do not bind a worktree path in a shell variable or change
their directory.

Slice 3 follows FT263. `bench worktree resolve <target> <path>...` stages each
named path and reports the remaining unmerged paths. When none remain, it names
the exact `git -C '<path>' merge --continue`, `cherry-pick --continue`, or
`revert --continue` command. The verb never continues the operation.

On success, exec prints the `worktree:` trailer and the child wall time.
