**FT254 (MEDIUM) — `bench worktree exec` is the comfortable path for multi-step work.**

The exec stdin help and `bench worktree show` shipped. What remains is `bench
worktree resolve`, the `--script` face, the timeout face, the `worktree:`
trailer, and the child-stdin decision. Every exec failure after target
resolution prints the absolute worktree path. Every earlier refusal names
`bench worktree list`.

A missing tree has no `path` or `exec` action, and both `list` and `exec` name
its recovery verb. A retained release names its reachable release form.

The follow-on guard accepts a non-Bench step before `bench worktree exec` and a
quoted `|` in the child argv. Every argument after `--` reaches the child, whose
stderr and exit code pass through unchanged. An exec grammar refusal exits 2, and its stderr starts with `usage:
bench worktree exec`.

`bench worktree exec` also receives ambient worktree-root or label-expanding
context, so callers do not bind a worktree path in a shell variable or change
their directory.

`bench worktree exec` accepts repeated `--env KEY=VALUE` entries before `--` as a validated child-environment face. This face avoids `sh -c`. A coordinator uses the exec or script venue for multi-step text work instead of direct pool-path scripts.

Slice 3 follows FT258. `bench worktree resolve <target> <path>...` stages each
named path and reports the remaining unmerged paths. When none remain, it names
the exact `git -C '<path>' merge --continue`, `cherry-pick --continue`, or
`revert --continue` command. The verb never continues the operation.

On success, exec prints the `worktree:` trailer and the child wall time.

`bench worktree exec` has a timeout face for a child that does not finish.

`bench worktree exec <target> --script <file>` runs a multi-step probe inside the
venue, so a probe cycle does not cost one call per step. `bench gate-prose`
defaults its root to the resolved worktree when it runs under
`bench worktree exec`. Outside exec, `bench gate-prose` defaults its root to `.`
when every operand is a file; the reviewer decides whether one rule covers both.
The review phase names
`bench worktree exec <integration-target> -- bench preflight review` as the
preflight venue, because the primary checkout derives the wrong tip.

The exec child inherits the caller's stdin, which the heredoc form needs. A child that reads an inherited pipe with no data blocks until the caller gives up. Decide whether exec closes the child's stdin when no heredoc feeds it; a call site cannot add a redirection because the CLI contract bans it.
