**The call-site map (folded from FT300).** A `bench preflight build` check that grades

**The registry binding.** The registry closure binds a whole package to its command
registry files. A ticket that changes no verb grammar then needs those files in its
`Writes:` line. A package that hosts a new command form can have no binding at all. The
binding names the grammar and registry source files of a package, and each independent
public inventory expectation of a new command form.

**The owner closure.** A ticket that reuses another file's rule, fixture, helper, home policy,
or span constructor needs that owner file in its `Writes:` line. The reviewer decides whether
the spec names each owner file when it slices the tickets, or whether preflight derives it. A
ticket that adds a liveness rule names how each existing retirement rule treats its entry.

**The premise closure.** Before a charge, preflight verifies each checkable tree
premise in the spec. It checks line counts, supported anchor kinds, net file
budgets, complete glob-member lists, and current headroom. A named symbol must import from
its calling seam. An owner sentinel or error names its exact owner and failure.
A bound or timeout names the owning symbol that proves its limit.

A reused test names the mutation and the observed red. A fence exclusion names
the exported symbol that crosses the boundary. A posture change supplies its
call-site census and writer probe. A claim about what a command prints cites every producer of that field.

Each decision predicate maps to one coverage row. Each row grades tracked
paths and names a supported anchor, or it reports the anchor gap before ticket
authoring. The author keeps the exact needle bytes for each extended sentence
and reads a renderer before a row promises output order. A confirmed discovery
gets its own ticket before the map locks.
