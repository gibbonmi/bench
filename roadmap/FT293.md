**FT293 (HIGH) — preflight stops predicting ownership closure, and a gate-found need widens a ticket's expected writes.**

The reviewer decided on 2026-10-17 that a ticket's `Writes:` line is an expectation, not a
complete authorization. A need that the gate finds can widen it inside the scope that the
reviewer approves at spec sign-off. This decision replaces the earlier plan to add five
closure members and a slicing-time projection.

Predictive closure cannot be complete. Each closure member is a static copy of a coupling
that a compile error, a test, or `bench structure` already reports, so each build finds a
coupling kind that the copy lacks. The copy also breaks the rule of one source per fact.

The removal spec has these parts:
- Delete the ownership closure, `--propose-writes`, `--breakdown`, the premise checks, and
  the guidance that repeats a check.
- Keep the consistency checks and the landing check that refuses a path outside the scope.
- Derive the spec scope from the tickets, so the spec holds no second copy of the fence.
- Add one plan verb that adds a gate-found path to a ticket's expected writes. A path
  outside the approved scope goes to the reviewer.
- Remove the contradiction in the delegate guidance that calls the fence both a refusal
  boundary and an expectation.

A read-only replay of six earlier builds sets the scope granularity before the spec: a
package prefix, a directory prefix, or a file.
