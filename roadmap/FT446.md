**FT446 (MEDIUM) — a retired cache store leaves with its cache, inherited registration has one owner, and the Darwin witness runs.**

The FT362 build delivered one lifetime owner and process-user protection. Three residuals
stay open.

- A retired cache store keeps no resource path. So the nested-store sweep cannot delete it
  when its test cache directory is gone, and about eight stores stay in `/dev/shm` per
  system run until a reboot. A retired store records its resource path, so the sweep and
  an absent-resource check can delete it.
- `bounds` and `runbinary` each build an inherited registration by hand. That is the same
  fact as the shared inherited run in `subprocess`, which needs a protocol parameter before
  `runbinary` can call it.
- The native Darwin witness for the builder group policy has not run. The reviewer deferred
  it on 2026-10-23. It needs a Mac host: run the Darwin policy test, then a probe that omits
  the group setup must turn it red. Decide whether a person runs it once by hand or a macOS
  job runs it, and where the result is cited, because the process-lifetime spec is retired.

The first two faces change the protection store and a `subprocess` seam, so they need a spec.
