**FT338 (MEDIUM) — a spec sweeps each retired claim and each affected caller before review, and pairs each rewrite with Forbid rows.**

A spec that moves or retires a guidance fact runs a reader sweep before the map locks. The sweep
searches each retired fact by its key terms and in normalized form, not only by its exact
bytes. It covers every phase command, the working agreement, agent definitions, harness
READMEs, public docs, the conformance helpers, and every test that consumes a registry output.
A spec that changes a shared resource also runs a writer sweep. The writer sweep names each
competing writer and the protocol that the row composes.

A spec that changes a public command also sweeps the `.github` workflows for each caller. A
spec that replaces a process stream walks the `os/exec` pipe rules before its first review
charge. An amendment that reverses a closed decision sweeps each touched spec for claims of the
old design before its review. Each numeric fixture row shows its arithmetic against its rule.

The spec verifies every current-code claim in its problem, solution, and
implementation sections against the tree. It names the source or marks the
claim uncertain. It rechecks an older decision source against its target and
history. Already-landed work becomes an implementation decision instead of a
new requirement. A recommendation that asserts current behavior names the
evidence read in the current session.

The implement phase prices this falsification pass. A legacy migration proves
that its new check is reachable from a real legacy input, and a replacement
probe follows that path.

Coverage for a real test records its provenance before its retired spec
disappears. Migrated decision prose states the actual decision instead of a
context-free gist such as `With lever 1 landed.` or `Bound it.`

The author verifies each recorded value against `DATA_HANDLING`. Review checks
each call-site posture, competing refusal, writer, publication cross-product,
and affected legacy input. Review exercises immutable tracked files,
transitioned specs, untracked descendants, and nested working directories. A
performance build measures after its first vertical slice and returns to the
spec when the measured wall refutes its premise.

The author walks each ticket's end state against every guard the spec adds. A
spec that changes authorship or the completion plan cites the review-plan and
assignment validators that it read.

Before the map locks, the author reads the enforcement surfaces for each new
CLI verb and conformance test. Before the first review charge, the author runs
the anchor self-check and the other named premise checks.

Each rewritten sentence takes a Forbid row for its retired text. A spec that moves a rule to
its owner also forbids the owner sentence at each former copy site. A Forbid row never removes
the last Require guard of a surviving duty; a Require row on the owner sentence comes with it.

Review treats a stale claim against an approved decision as a finding, even when an axis
reports it as advice.

The edits land in `craft-spec`, `craft-gate`, and `craft-review` under the `craft-synthesis`
discipline.
