**FT380 (MEDIUM) — every plan commit passes the coverage parser and build preflight before dispatch.**

A plan commit can change the coverage map, a ticket fence, or the plan JSON. The Markdown
lane does not run the coverage parser, and a plan commit after a chunk freeze changes the
frozen review. A `Writes:` expansion also needs the spec fence union and the registry
closure.

`bench commit --preflight-build <slug>` runs the build preflight after a commit, and the
build preflight parses the coverage map. The guidance requires this form for each plan
commit before the next dispatch. A check before publication stays open. A plan commit after a chunk freeze joins the successor's review delta. The lane
enforcement graduates only on a `bench commit` repro of the skipped parser.

The build preflight also checks the chunk table against the coverage map. A red
`check-floor` row blocks the next charge and the review charge, not the publication. The
floor in the commit lane stays open here.

The last chunk has no successor, so a plan commit after its tip forces a refreeze. A coverage-cell citation and the test that it cites land in one commit. The next chunk base is the predecessor tip when a comment-only correction follows that tip.

A spec text change after a chunk's refreeze invalidates its author verification, because the
source digest covers the spec bytes. The implement-spec guidance batches a review's prose-only
spec corrections before the repair's refreeze, or defers them to the next plan commit before
a ticket dispatch.
