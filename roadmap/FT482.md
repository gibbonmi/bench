**FT482 (MEDIUM) — a cache release never seals a generation for a live protected user, and a Markdown-only commit starts no background grade.**

Today one leaked descendant of a test run keeps its protected-user registration. The cache
holder's release then seals the resource generation, and every later `bench test` on that
HOME refuses with "the resource generation is sealed" until the descendant exits. A user
whose actor and process group are dead on the current boot still counts as live. The
policy crosses the `gocache` and protection seam, so it needs a spec.

The reviewer decided both terms on 2026-11-07. A release does not seal a generation while a
protected user is live. The protection owner treats a user as released when its actor and
its process group are dead on the current boot.

A record commit that changes only Markdown starts a background grade. When the cache
generation is sealed, that grade holds it, and the next lane commit refuses. A commit with
no graded build input needs no background grade. The reviewer decided on 2026-11-07 that
this face is part of the same spec.
