Class: fix.

The reviewer decided on 2026-10-09 that an unrelated landing does not move `main` while a
chunked build is open:

- `bench worktree land` refuses a landing that is not the open build's own landing. The
  open-build state lives in the shared intent ledger, under the intent lock. The refusal
  names the build and the gap to wait for.
- The window opens at `bench commitment start`. It closes on completion, on `bench
  commitment block`, or on abandon, so a stopped build cannot freeze `main`.
- A gap opens at a recorded chunk checkpoint, and the next chunk dispatch closes it. The
  build folds `main` once, before the author dispatch, so the charge pins the new base. The
  build's own light-path dispatches also wait for a gap.
- An override is a recorded, reviewer-owned flag with a reason. An agent cannot grant it to
  itself. A move after the last checkpoint occurs only through the override.
- A new record form accepts a fold-delta review. A clean fold needs no review round, and
  only conflict-resolved hunks get review. The final checks include the packages of the
  merged test files.
- Back-out is a revert commit that lands from a fresh worktree with the override. `main` is
  never reset.

The spec decides each mechanism inside these bounds. The `merge-fold-red` refusal face
routes a fold that adds a red to this row. A refusal for a moved destination names `bench
worktree merge` and the landing rerun, not `bench doctor`.
