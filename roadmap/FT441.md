**FT441 (MEDIUM, decision required) — the spec author re-reads each cited source and walks each lifecycle, and the spec review grades rows against the tree.**

Each recent spec stage took two to five review iterations. The spec fork authors from
compressed findings and does not re-read the sources that it cites. It does not walk the
lifecycle of each state that a row changes, so deadlocks surface in review. The spec
review grades the row stories, not the tree, and it re-grades only the repair, not the
rows that depend on it.

The faces are:

- The fork re-reads each cited source and walks the lifecycle of each changed state.
- The review grades each row against the tree and re-grades the dependents of a repair.
- A spec that edits another staged spec names the bound deliverable identity that it breaks.
- A deleted grader names the readers of the data that it kept valid.
- A second production derivation of one fact is a reviewer decision, not an implementation decision.
- An inherited row keeps a seam that can produce its failure.
- A projection that leaves identity to its caller has a negative-identity row for each caller.
- A slice that ports a differential witness ports its durable reference too.
- Before the review charge, the author names the fixture event that reaches the candidate set of each "excludes" or "per group" row, and a per-group limit uses at least two groups.
- A measurement ticket tests the proposed change against each exec child that mutates source, such as `bench probe`.
- The plan-only preflight grades two ticket rules: tests without behavior is not a ticket, and a seam ticket is its own chunk. It also grades the mechanical candidates among the quantified spec clauses.

The reviewer decides where edge cases go: to mutation probes, or to a hostile-checklist
walk that the spec review grades. The reviewer also decides whether a tests-only ticket is
ever legitimate, such as a test-gap light path, and which mechanical candidates the
preflight grades. The kit edit and the preflight rows follow those decisions.

The FT449, FT314, and FT450 spec stages each paid two or three spec iterations and two
ticket iterations. Their findings add these faces. A projection or a second reader of a
decided fact names its owner function and guard order. The author walks each new or reused
refusal route to exit 0 at the member floor and at the bound. The slicer traces each input
of a reused owner to a value at the new call site, and confirms that each row's test
package can reach its seam. The spec review compiles each planned probe mutant at the
reviewed base and traces it to the assertion that it claims. A chunk-table walk, where the
chunk of each row's ticket lists the row, is a new mechanical candidate.

The builds of 2026-10-27 to 2026-10-29 add five faces. A new record-entry producer names its one writer, and a row grades a produced entry through the real grader. The reader sweep of a retired rule covers `.bench/BENCH.md` and `docs/adr`. A rule that selects a commit from history names a transition and runs over the repository's own history. Each planned Require needle is graded against the anchor admission classes. Each plan probe goes red with the ticket's diff and stays green without it.
