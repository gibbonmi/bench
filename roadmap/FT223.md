**FT223 (LOW, decision required) — `bench commit`'s inherited-verdict refusal misreads as a red gate.**

`internal/landing/landing.go` refuses prospective authorization
whenever the composed tree's verdict is `Kind != authorization.Green`,
including an inherited (partial-evidence) verdict that is not a failure.
`error: prospective authorization refused: inherited` names an internal verdict
kind, not an operator action. A caller-printed `gate: red` alongside it
misreports a partial verdict as a failing one, costing a fresh gate run to
disprove. The reviewer decides between two fixes. The first fix rewords the
refusal in operator terms, names `bench gate --fresh` as the next action, and
stops the `gate: red` print. The second fix makes `bench commit` escalate to a
fresh prospective gate instead of refusing.

The same refusal has a second face. When authorization refuses for an
infrastructure cause, it prints only the kind. The subject's open reason,
for example a declared environment variable that is absent, stays hidden, so
the caller debugs the wrapper by hand. The refusal names the open reason.
