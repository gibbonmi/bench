**FT336 (HIGH) — every Bench verb prints its verdict and its next action by default, and `bench worktree exec` bounds its child output.**

The reviewer set this row as priority 1 and classified it as a critical bug. A Bench response
that is longer than 10 lines is a defect.

Each verb prints what the agent acts on: the verdict and the next command. A green table
becomes one summary line. Detail stays behind `--full` or in a file that the response names.
Every payload has a byte bound and a line bound. Per-row help rows go away.

`bench worktree exec` is the only route into a worktree, because the follow-on hook refuses a
pipe or `tail` after a Bench call. So every byte that an exec child prints reaches the agent
context. Exec bounds the child output, or it writes the excess to a file and prints its path.
The same bound applies to each Bench verb that exec runs.

The spec audits every verb that an agent runs in a worktree. For each verb, it records what the
agent acts on. It measures requests and context together, because the cost driver is
requests multiplied by context. The census adds the output bytes of each verb. The audit did
not measure `bench worktree create`, `release`, `reauthorize`, `merge`, or `land`, because each
one changes state.

These faces join the spec:

- `bench preflight evidence` prints a small summary by default. Each source stays behind an
  explicit request or a `--to <dir>` spill. This face crosses the bounded-page ADR.
- A compound verb commits, runs the worktree build, and runs the build preflight in one call.
- The reviewer decides whether a hook and platform rule allows safe chains of Bench calls,
  because the no-`&&` rule doubles the call count.
