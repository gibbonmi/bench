**FT240 (EXPERIMENT, decision required) — iq retrieval experiment: token-budgeted search against the EKS monorepo.**
Evaluate the standalone IntenTIC `iq` CLI against the large EKS monorepo before
any integration — it does not become a Bench dependency on intuition. Three
arms through FT231's harness: rg plus file reads plus the ordinary agent
workflow; current Bench progressive disclosure; current Bench plus `iq`.
Representative tasks: locate an onboarding implementation seam; trace a symptom
through Kubernetes, Terraform, GitOps, and observability configuration;
identify the blast radius of a proposed change; find the tests that should
exercise a changed component; orient a fresh agent in an unfamiliar part of the
monorepo. Capabilities under test: `map` for repository orientation, `impact`
for one-hop dependency and test reach, `hotspots` for churn × complexity,
definition/reference/structural/git-history search, ranked path:line anchors,
and token-budgeted output with explicit ambiguity and continuation.

Adoption rule: adopt only if the measured task-success or efficiency gain
justifies the Node, model, and index requirements and one more failure mode.
The expected value concentrates in difficult cross-vocabulary searches, not in
obvious single-file lookups — a null result on easy tasks does not decide the
question. The harness result then adopts, rejects, or narrows the integration.

Source: the reviewer's 2026-08-20 IntenTIC feature assessment (the `iq` CLI
and its iq-bench evidence; assessment prompt only — neither the IntenTIC tree
nor `iq` itself was read or run).
