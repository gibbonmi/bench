**FT239 (MEDIUM, decision required) — the adapter seam: a versioned capability matrix, and parity tests that prove one core.**
Two halves, one seam. First, a small versioned capability record per supported
provider × harness combination, describing mechanics rather than model quality:
steering during an active turn, structured user questions, tool-permission
controls, hooks, MCP support, subagent support and isolation, effort selection,
persistent tasks or plans, resume and recovery behavior, structured output and
exit-status support, headless execution. A matrix test fails when a supported
runtime lacks an explicit row, and `bench status --route` consumes this data —
skills and adapters stop inferring capabilities independently. This makes the
Claude-outage path and model-free degraded operation explicit and testable, and
it generalizes the per-surface verdict FT24 keeps in `.bench/BENCH-reference.md`
Hook Layers into one queryable source. The matrix is data for the 2026-08
capability audit's A3 front door: A3 builds `bench status --route`, and this
record is what that route consumes instead of per-skill inference. FT222's routing-source decision is the
adjacent settlement: whichever file wins there is where this record lives.

Second, strengthen one-implementation-behind-every-entry-point as a tested
property. The deterministic Go core is already authoritative for routing and
status, gate evaluation, worktree lifecycle, commit and landing, preflight and
coverage, release transitions, and evidence rendering; adapters translate input
and presentation and must not hold a second opinion about state or validity.
Add parity tests that send equivalent requests through each adapter — slash
command, Codex skill, hook, CI — and assert the same core result, so local
verification and CI execute the same implementation.
