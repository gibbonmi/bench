**FT239 (MEDIUM, decision required) — the adapter seam: a versioned capability matrix, and parity tests that prove one core.**

Two halves, one seam. First, a small versioned capability record per supported
provider × harness combination, describing mechanics rather than model
quality: steering during an active turn, structured user questions,
tool-permission controls, hooks, MCP support, and subagent support and
isolation. It also records effort selection, persistent tasks or plans,
resume and recovery behavior, structured output and exit-status support, and
headless execution. A matrix test fails when a supported runtime lacks an
explicit row, and `bench status --route` consumes this data. Skills and
adapters stop inferring capabilities independently.

This makes the
Claude-outage path and model-free degraded operation explicit and testable.
It also generalizes the per-surface verdict FT24 keeps in
`.bench/BENCH-reference.md` Hook Layers into one queryable source. The matrix
is data for the 2026-08 capability audit's A3 front door: A3 builds
`bench status --route`. This record is what that route consumes instead of
per-skill inference. The record is a Go table in the core, projected by
`bench harnesses` (reviewer decision, 2026-08-26). It shares no file with
FT222, which decides per-project tier policy alone.

Second, strengthen one-implementation-behind-every-entry-point as a tested
property. The deterministic Go core is already authoritative for routing and
status, gate evaluation, and worktree lifecycle. It is also authoritative for
commit and landing, preflight and coverage, release transitions, and evidence
rendering. Adapters translate input and presentation and must not hold a
second opinion about state or validity.
Add parity tests that send equivalent requests through each adapter — slash
command, Codex skill, hook, CI — and assert the same core result. So local
verification and CI execute the same implementation.

Boundary, decided by the reviewer 2026-08-20: IntenTIC is a pattern source and
a future compatibility target, never Bench's foundation. This restates the
capability audit's A12 DELETE doctrine from a second, independent source. That
doctrine has no work-state store, no context compiler, no typed claim graph,
and no new spine.

It carries the board-side record A12's acceptance criterion
asks for. It also revisits only if FT231's harness observes a failure the
incremental items do not close. Explicitly deferred: a browser workspace or persistent sandbox
daemon, an authentication or tunnel plane, and an extension marketplace. Also
deferred: the IntenTIC deployment engine, provider-native memory as
authoritative Bench state, a general knowledge graph or context compiler, a
new work-state store, and an AI release gate presented as the deterministic
oracle.

Any IntenTIC-inspired feature must preserve the
deterministic core and gate authority, work across supported harnesses or
degrade explicitly, and keep authoritative work state repository-native. It
must also improve measured outcomes (FT231), and add less operational
complexity than the failure or cost it removes.
