**FT318 (MEDIUM, decision required) — the completion form records a capability-blocked row's decided value, and `bench record` closes its native-operation residuals.**

`bench record` writes the assignment, chunk, verification, review, amendment, and
completion entries of the review record. It computes each digest and parses the whole
record before it writes. A stale plan digest at the chunk writer routes to the amendment
form. Each checkpoint refusal names the form that repairs it, and verification imports a
complete probe result.

Four faces remain:

- The completion form records the decided value of a capability-blocked row. A
  capability-blocked row needs evidence that the build host cannot produce. Decide at spec
  approval how such a row reconciles. The decision names the value that the completion
  checkpoint records for the row, and it names the owner of the open evidence. This face
  needs that decision before the writer encodes it.
- A persisted record of executed `bench test` runs stops exit codes from being
  author-stated.
- The refusal repair binds each substituted value to the flag declaration of its form.
  Today a second table spells the repair flags again, so a renamed flag drops its value
  silently. The binding is a new seam.
- Decide when a spec-prose correction after a chunk tip can retain the chunk's
  verification evidence. Any executable, acceptance, ownership, or evidence change still
  requires the verification that its changed subject needs. The decision must distinguish
  those changes from prose that changes no graded requirement.

`bench record assignment` derives the assignment from its worktree, or it refuses a mismatch.

`bench record ticket` takes the plan's chunk base for a first chunk, replaces its own rows
after a refreeze, and names the reset-and-restage route when an evidence id already exists.
A `bench record pickup` form appends the review pickup, and a `bench record note` form
appends one orchestrator prose section outside the fence. `bench record excerpt` accepts a
saved probe-set answer, or the probe warns when its selection differs from the planned one.

No Bench form writes the version 2 delegate amendment of a completion plan, its floor
rows, or the citation form of a covered coverage cell. Each build edits the plan fence by
hand with python3 or `sed -i`. A `bench spec` form writes each of these edits and validates
the result before it returns.

FT445 shipped the test-only confirmation of a delegated repair.

`bench record verification --final` stages the last retained response, as
`bench record excerpt` does. `bench record excerpt` returns the inner spill path, so
`--probe-result` never takes a spilled frame.

Graduation trigger for the probe-staging face: a `bench record ticket` run that stages a retained probe A as unstaged requirement B and exits 0.

Faces from the November builds:

- `bench record assignment` takes a staged spec, ticket, or widen edit in the same plan commit, and the first assignment shares the commit that declares the version 2 plan.
- `bench record ticket --witness <file>` writes the author's witness reds in the author's own record commit.
- `bench record review` and `bench record verification` read the excerpt from stdin, and `--final` records several requirements, including `system`, from one result file.
- `bench probe --mutants` stages each row under `--requirement`, and the `bench record ticket` excerpt refusal names only the requirements that block it.
- A plan verb adds a ticket to a chunk and moves requirements, and `bench record amendment` answers "no record yet" with no `next=`.
- An assignment-only plan change keeps the record plan digest current.
- The reviewer decides whether the checkpoint accepts a verification from any session in the ticket's assignment history at the current pair.
