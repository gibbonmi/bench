**FT318 (HIGH, decision required) — the review record has a native writer.**

Each coordinator session wrote the review record fence with a script: the chunk entry,
the round entry, and the completion entry. The review phase names the pickup payload,
but no verb writes it. FT254 rules that a raw-call count alone selects no new command,
so this row needs a decision.

Decide whether a `bench review record` verb earns a seam. The alternative is a smaller
payload that the edit tools write without a script.

**The record content (folded from FT313).** The record uses stable evidence identifiers
and gives each missing row one reason. It stores compact event summaries with source
digests, so a consumer can reconstruct the record and validate the same evidence.

**The write-time validation.** The writer validates the record when it writes it. An outcome
that conflicts with its findings then fails at once, not at the next review charge. A verb
renders the record and its plan amendments from the author and axis returns, so that no
coordinator writes a JSON builder script. The reviewer listed this compound verb among the
FT336 and FT337 research faces.

The writer records fenced review evidence without a raw script in the assignment
worktree. The plan identity hashes the completion-plan fence and ticket bytes.
Unrelated spec prose does not change that identity. An amendment records each
intentional identity change. A spec edit after an accepted chunk records its
amendment in the same commit. The plan records all initial assignments before
the first chunk freeze.

Only a repair assignment then changes the plan digest.
