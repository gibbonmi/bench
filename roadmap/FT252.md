**FT252 (MEDIUM) — a Bench verb moves a retained worktree, or a sibling assignment, onto a new base, and folds a sibling's diff into it.**

No verb moves a retained worktree to a new base. `create --refresh`
refreshes the pool, not the checkout, and `create` takes no base ref. So an
integration source that must absorb an amendment reaches its base only
through raw Git inside the worktree. A delegate worktree that must start from
the integration tip has the same route. That route sits against this repo's own rule that the
lifecycle runs through Bench verbs. The residual survives the FT238 hygiene
batch, which shipped the other worktree-path faces.

The fold is the second face. A coordinator folds one owned worktree's diff into
another owned worktree with `git apply`, `git apply --3way`, or a whole-file `cp`.
The verb refuses on conflict and names the conflicting paths. No verb recovers a
worktree base after the default branch advances; the guidance names no sanctioned
fallback either. `bench worktree reauthorize` replaces a lost request token and does
not move a base.
