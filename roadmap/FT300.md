**FT300 (MEDIUM) — ticket slicing fences the file a ticket's own change moves and names the fixture that reaches a refusal state.**

`ticket-slicing` was the repair cause in four of the twelve binary-freshness
repair rounds, across three of the seven tickets that needed repair. Every
round shared one shape: the fence omitted a test or a registry that the
ticket's own change moved. `craft-tickets` needs a rule that a ticket's fence
includes the file its own change will relocate, not only the files it starts
in.

When a row binds `PATH` in a package with a pinned serial set, the fence names
the serial ceiling file. Ticket slicing places a new test in a file with
structure-budget room.

Class: fix.

When a ticket moves a captured snapshot or registry row, its `Writes:` fence
names that destination file. FT300 owns this requirement. It coordinates the
overlap with FT293, but does not move it into FT298. When a ticket adds a canary
fixture, its fence names the fixture directory, not only its files.

A lane-check ticket proves its check through the real lane over a composed tree,
never through a shell stand-in.

A refusal-state acceptance row names the fixture path that reaches the state.
Before a slicer names a refusal state, the slicer reads that fixture and
confirms that the verb's own seams reach the state. A defensive check with no
reachable input is not an acceptance row.

Occurrence: 2026-09-04 handoff-sections retro — a moved snapshot was absent from the ticket's `Writes:` line.

When a ticket's `Writes:` line names a path that a canary fixture pins, the
fence names that fixture too.

Before the first review charge, the slicer maps each coverage row's cited test
file to the owning ticket's `Writes:` line. It also maps each anchored
needle's registry files to that line. When a posture change reds a fixture helper, the slicer enumerates every
call site of that helper before the map locks. A `bench preflight build` check
that grades that map is a candidate face, and it coordinates with FT293.

Before review, cited verifier rows name the exact checks performed. Preserve and move logic walks head, tip, and checked-out-ref shapes.

The slicer performs a source-clause coverage pass and an executable route pass before it locks a ticket.
