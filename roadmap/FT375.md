**FT375 (MEDIUM) — the build preflight reports spec staleness, and the staleness pass audits only drift and red rows.**

The staleness pass is now a light fixed procedure. Its inputs are still resolved by hand,
although the spec holds each one. `bench preflight build` has no row for drift, for a
cited symbol, or for a cited test.

The `rows-owned` and `rows-membership` rows already compare the `Covers:` lines with the
coverage map. The build preflight gains three rows:

- A drift row lists each fenced path that changed from the spec's pinned commit to the
  source tip.
- A cited-symbol row reports each symbol of the cited-symbols table that does not
  resolve.
- A cited-test row reports each existing seam test that is absent and each planned test
  that exists.

When these rows are green and the drift row is empty, `/bench-implement-spec` dispatches
no staleness pass.

The staged spec is `specs/preflight-spec-staleness/spec.md`. The staleness report also
short-circuits when the build base equals the commit that landed the spec. It also
short-circuits when no later commit changed a ticket `Writes:` path, a cited file, or the
`bench consumers` blast radius of a cited symbol.
