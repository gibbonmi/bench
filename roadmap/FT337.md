**FT337 (HIGH) — review evidence cost follows the changed code, not the whole spec.**

The reviewer classified the review token cost as a critical bug. `bench preflight review
--charge` builds the diff source from `main`, so the source carries the whole spec, every
ticket, and the review record. Its fixed 8 KiB pages shift their digests when an earlier byte
changes, so no page is reused across rounds. The fix pages the diff source by file, or leaves
out the spec, ticket, and review-record paths. Then an unchanged file keeps its page digests,
and a reader never reads bytes again that it already holds.

The review phase already dispatches a fresh narrow axis for each round, and the coordinator
keeps only the manifest and the metadata. That narrow shape is provisional. The spec records
what each narrow round read and found. It then runs one full-retrieval control review of the
same diff, so that a miss shows before the narrow shape becomes the permanent rule.

The implement phase names one order: the author record commit, then the review charge, then
the axis dispatch. A record commit after the charge moves the tip, and the prepared evidence
then fails its check-current step.
