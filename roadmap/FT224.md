**FT224 (MEDIUM) — a lifecycle refusal names the component that failed and the command that fixes it.**
The worktree and landing refusals report that something did not match without
saying what, so a one-token operator error costs a session of diagnosis. Two
observed faces share the defect. The landing's identity check collapses four
distinct failures — a request-digest miss, an absent assignment, a non-active
state, and a path mismatch — into one string naming all four; the same shape
repeats at the resume and ownership call sites. And the release refusal
directs the caller to re-run with `--discard-ignored`, a flag that command does
not accept, because it belongs to `bench worktree clean`.

The fix is one property, not three patches: a refusal names the component whose
check failed and, where a sanctioned recovery exists, the command that performs
it. Every refusal message must be reachable from a test that asserts which
component it named, so the four-way string cannot come back.

Occurrence: 2026-08-18 bench-front-door landing — `worktree land` refused with a four-cause string; the intent ledger falsified three causes and a digest comparison confirmed the fourth, after the session had already been blocked once.

Two further faces share the property. `bench worktree land` refuses a light-path
worktree because it requires a reviewed spec's `spec.md` and ownership fence,
and a light-path spec is a tickets-only directory; the refusal names neither the
light path nor the fast-forward as the sanctioned route. Whether the verb should
instead serve a tickets-only spec is a reviewer decision this row carries. And a
gate whose root and kit disagree drops phases and reports an unstaged
environment rather than naming the disagreement, so a clean tree reads as red
for a cause nobody set.

Occurrence: 2026-08-19 FT228 build — `bench worktree exec` mis-rooted the kit, and the gate reported an environment skip and a red clean tree instead of naming the two dropped phases.
Occurrence: 2026-08-19 FT228 side-track — `bench worktree land` refused the light-path worktree, so three commits reached `main` by `git merge --ff-only`.
Occurrence: 2026-08-19 FT228 close — `bench worktree release` refused on ignored residuals and pointed at `--discard-ignored`, a flag `release` itself rejects.

A next-step shares the property from the other side: `bench spec retire`'s
next-step names the `ROADMAP.md` row but not the `roadmap/FT<n>.md` detail file,
so the orphan check reds a full gate run later. The next-step names both
deletions.

Occurrence: 2026-08-20 ft230 retirement — the retirement gate caught the orphaned `roadmap/FT230.md` after `bench spec retire`'s next-step had named only the ROADMAP row.
