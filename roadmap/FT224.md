**FT224 (MEDIUM) — a lifecycle refusal names the component that failed and the command that fixes it.**
The worktree and landing refusals report that something did not match without
saying what, so a one-token operator error costs a session of diagnosis. Three
observed faces share the defect. The landing's identity check collapses four
distinct failures — a request-digest miss, an absent assignment, a non-active
state, and a path mismatch — into one string naming all four; the same shape
repeats at the resume and ownership call sites. The reviewed-landing spec-byte
check refuses correctly but names no remedy, leaving the operator to infer that a
review-amended spec must land on the destination first. And the release refusal
directs the caller to re-run with `--discard-ignored`, a flag that command does
not accept, because it belongs to `bench worktree clean`.

The fix is one property, not three patches: a refusal names the component whose
check failed and, where a sanctioned recovery exists, the command that performs
it. Every refusal message must be reachable from a test that asserts which
component it named, so the four-way string cannot come back.

Occurrence: 2026-08-18 bench-front-door landing — `worktree land` refused with a four-cause string; the intent ledger falsified three causes and a digest comparison confirmed the fourth, after the session had already been blocked once.
