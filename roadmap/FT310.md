**FT310 (MEDIUM) — a guard refuses a file-tool write to a tracked path in the primary checkout.**

The primary checkout takes writes only through a landing, and the Bash guards
already refuse the raw git route there. The Claude Code file tools have no such
guard. Read is not a write, but Edit and Write are. An agent edit to a tracked
path in the primary checkout therefore lands silently, and only `git status`
catches it. The revert then needs a user-run `git checkout`, because
`block-dangerous-git.sh` correctly refuses the agent's own.

The guard refuses an Edit or a Write whose target is a tracked path under the
primary checkout, and it lets a git-ignored path through. It composes the
existing guard family: the hook script, the harness wiring, the `bench guards`
manifest row, and the harness-record conformance. Codex has no file-tool hook
surface. That parity question belongs to FT24 and stays out of this row.
