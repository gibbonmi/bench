**FT451 (MEDIUM) — the gate grades each lane-passed tip in the background, so a checkpoint or a landing looks up its verdict.**

The checkpoint gate starts only after the record commit. The prepared run of FT445 is
opt-in at two guidance points. A background grade of each lane-passed tip makes most
checkpoints and landings a lookup instead of a run.

The design needs the grade key of FT314 and a resource census under ADR 24. Superseded tips
waste runs, and the host runs `-p=4` with up to two testing delegates.

FT445 shipped two reuse pieces that this row builds on. The chunk checkpoint key leaves out
the review record, and a test-only delta checkpoint writes its own green, which no landing
reads. A background grade extends the prepared run to every lane-passed tip.

A background run is an exec child of the worktree. It must hold under each exec child that
mutates source, such as `bench probe`, which FT445 ticket 12 found to break a reused binary.
A fixture's nested gate that outlived its probe kept a cache generation sealed, and FT372
holds that family.

In the FT445 repair cycle the author's own runs took about 26 of 40 minutes, so a faster
gate shortens only part of the cycle. FT448 owns the rerun cost.
