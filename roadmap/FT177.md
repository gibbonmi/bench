**FT177 (MEDIUM) — a stale `dist/bench` invalidates tests and its promotion-broker manifest.**

Contract CLI tests reject a `dist/bench` older than the tracked Go sources,
because stale bytes can only yield a false pass. `bench commands --brief`
likewise verifies source/binary identity, or refuses with a repair action. And
`bench doctor` names the mismatch and its fix. This includes the case where the
binary was built at a worktree instead of the kit root. That case today
produces a refusal naming the wrong root.

A `--full` landing preflight checks the destination binary seal and names the
rebuild before the review-to-landing transaction begins.

A hand rebuild can replace the manifest-bound promotion broker without a new
digest. The next landing then refuses before it reads the request. The repair
contract must decide whether the build publishes the broker atomically or
reserves publication for `bench doctor --fix`.

The tagged systemtest suite gets one wrapped invocation that supplies the
run-binary and kit variables. Then a hand probe fails on the subject, not on
plumbing.
The follow-on guard reads the binary's answer on every Bash call. When a stale
`dist/bench` answers `unknown subcommand`, the guard blocks every call, not
only Bench ones. Decide the guard's posture on that answer: fail open with a
warning that names the rebuild, or refuse with the rebuild as the next action.

The landing also needs one decision for a manifest that reports `dev` against
the installed package. It can rebuild through `scripts/go-build.sh`, publish
the broker, and continue. A digest mismatch remains a tamper refusal. Remove
every bare build path so the version stamp and manifest have one producer.

A landing line that says the promotion broker source changed is a tail duty:
rebuild `dist/bench` through the stamped build and run `bench doctor --fix`.
Before a landing, `bench worktree land --help` from `main` proves the broker;
an exit 127 names the mismatch.

The landing tail names bench repair as the broker-refresh route. In the kit source checkout bench repair refuses, because it reads the npm pin manifest binary-pins.json that only the release artifact carries.

Decided 2026-09-02. Staleness is a mismatch between the stamped source digest
and the tracked Go sources' digest, never an mtime. On an `unknown subcommand`
answer, the follow-on guard warns and passes a non-Bench call, and it refuses a
Bench call with the rebuild named. The stamped build publishes the broker
atomically, and `bench doctor --fix` stays the repair. A `dev` manifest
rebuilds through the stamped build and continues; a digest mismatch stays a
tamper refusal.

The landing advertisement is the wrong side. The landing line
names the stamped rebuild and `bench doctor --fix` for the source checkout, and
`bench repair` stays the installed-kit route.
