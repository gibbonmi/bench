**FT213 (MEDIUM) — `craft-delegate` visit: worktree isolation, end-of-life, and probes that prove something.**
One kit edit under `craft-synthesis` over a single owner surface, batched
because each clause separately pays a full gate for a few lines.

A read-only delegate reading a tree the coordinator is about to grade gets its
own worktree — "needs no worktree; say 'do not edit any file' and mean it" still
hands it full write access to the graded tree — or the coordinator verifies the
tree unchanged before the landing gate. A delegate's reading of a gate skip or
gate-adjacent signal is a claim, not a result: plant the corresponding break and
run the oracle before believing either reading. `RestoreMutationFixture` refuses
`dst == root` rather than silently no-op when a caller passes the real root.

Release is the creating request's default end of life for a delegate worktree;
clean-then-`bench resume-clean` is the recovery pair. A parallel repair batch
declares which files its tickets expect to touch in common, so the coordinator
can order ports to minimize conflict surface.

A coordinator's mutation probe requires a *behavioral* mutation — a probe that
fails to compile is indistinguishable from a passing one, and a probe mutating
provably-redundant code passes by construction. Probing a tracked file that has
pending changes copies it aside rather than using `git checkout --`, which wipes
the whole in-flight diff and not just the probe; that rule is correct today but
sits as a parenthetical, and becomes a named step in the mutation-probe
checklist. A fan-out is reported as launched only after a liveness check, not a
successful spawn.

Disjoint ownership fences across sibling tickets do not license concurrent
writers in one tree: the lever for parallelism is separate worktrees, and a
build that wants both serial verdicts and parallel delegates says which it is
buying.
