**FT213 (MEDIUM) — `craft-delegate` visit: worktree isolation, end-of-life, and probes that prove something.**

One kit edit under `craft-synthesis` over a single owner surface, batched
because each clause separately pays a full gate for a few lines.

A read-only delegate reading a tree the coordinator is about to grade gets its
own worktree. "Needs no worktree; say 'do not edit any file' and mean it" still
hands it full write access to the graded tree. Absent that worktree, the
coordinator verifies the tree unchanged before the landing gate. A delegate's
reading of a gate skip or gate-adjacent signal is a claim, not a result. Plant
the corresponding break and run the oracle before believing either reading.
`RestoreMutationFixture` refuses `dst == root` rather than silently no-op when
a caller passes the real root.

Release is the creating request's default end of life for a delegate worktree,
and clean-then-`bench resume-clean` is the recovery pair. A parallel repair
batch declares which files its tickets expect to touch in common, so the
coordinator can order ports to minimize conflict surface.

A coordinator's mutation probe requires a *behavioral* mutation. A probe that
fails to compile is indistinguishable from a passing one. A probe mutating
provably-redundant code passes by construction.
A probe of a live-tree anchor or marker runs through the gate, not through the
conformance package alone. Only the gate's entry test grades the live tree.

Probing a tracked file that has
pending changes copies it aside rather than using `git checkout --`. That
command wipes the whole in-flight diff and not just the probe. That rule is
correct today. It sits as a parenthetical, and becomes a named step in the
mutation-probe checklist. A fan-out is reported as launched only after a
liveness check, not a successful spawn.

A repair charge names the property the fixture must make
red-capable and lets the delegate derive the shape. Prescribing the shape buys a
vacuous test whenever the prescribed one is not red-capable.

Disjoint ownership fences across sibling tickets do not license concurrent
writers in one tree: the lever for parallelism is separate worktrees, and a
build that wants both serial verdicts and parallel delegates says which it is
buying.

A write charge names the root conformance pass and the file's wrap width in its
verification list. It treats a coverage-row citation in a test doc as a
reference to keep. It reads a background commit by its `committed` line. A
review round declares its iteration cap before the first charge. A re-review
charge names the folds and asks only for findings above the blocking bar;
`bench-write-spec` carries the cap sentence.

A write charge names `bench worktree exec "<label>" -- <command>` as its only
command form. It uses the absolute worktree path only for file reads and edits.
It does not offer `cd` into that path as an alternative.

A pure test-addition charge names the production mutation each new test is
proven against. Then the delegate cannot return a test that is green by
construction.

A running `bench commit` is active until its process exits. A reported red
does not authorize tree edits while later phases or cleanup can still run.
The coordinator waits for the terminal exit before diagnosis or repair. This
clause joins from FT245.

A charge that shells out names the branch-native census's allowed process
seams. It never backgrounds a test run. A moved or reflowed anchor runs the
fixture-bite check in the focused verification list. A coordinator probe writes
through the writer the test captures, not an ambient stream the test ignores.

Before landing, the coordinator compares the destination tip with the frozen
base. It grades each destination change that a new oracle check reads. A hand
verification does not close an acceptance row without a named red-capable test.

A write charge states that its ownership fence is a refusal boundary above any
mirror-every-registry instruction. The delegate reports an out-of-fence registry;
the delegate does not edit it.

The checkpoint ticket records a reviewer decision when the decision occurs
during a build. Later review reads the decision.
