**FT349 (MEDIUM) — the ticket checkpoint enforces the check floor and refuses a leftover `planned` citation.**

Two guidance rules shipped on 2026-09-27 with no enforcement. The first is the
ticket check floor in `bench-implement-spec`. Before the ticket commit, the author
runs root conformance and the tests of every package the ticket writes. The author
also runs the whole `cmd/bench` package for a changed public response or embed
pattern. The second is the `planned` marker that `bench coverage --check` exempts.
A seam cell may name a test that does not exist yet, if the cell holds the word `planned`.

At the ticket checkpoint, both rules get an executable owner. The build preflight
or the lane of a ticket commit derives the floor from the ticket's `Writes:` line.
It refuses a commit whose checks omitted a package in that set. The same checkpoint
refuses a `planned` citation for a row that the committed ticket covers. By then
the test exists, or the row is not covered. The spec decides which surface owns
each refusal, and it names the derivation from `Writes:`.
