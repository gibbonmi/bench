**FT445 (HIGH) — a chunk repair commits once with no restage, and the checkpoint gate alone grades the chunk tip.**

A tip move in a multi-ticket chunk makes every ticket session restage its record at the
new freeze tip. Each session reruns its whole check floor, although the checkpoint gate
already runs the whole project gate at that tip. One repair cycle takes 45 to 60 minutes,
and most of that time is the serial restage. The target is 11 to 14 minutes for a
one-file test-only repair.

The reviewer approved this shape on 2026-10-23, from a joint opus and fable consultation:

1. Each ticket's evidence binds to its own commit tip, and the restage goes away. The
   whole checkpoint gate alone grades the chunk tip.
2. The repair session runs each owed check once, at its own commit.
3. A test-only repair closes through the test-only confirmation form, not a three-axis round.
4. Each repair writes one plan commit, and only the last plan commit runs the preflight build.
5. The gate starts when the repair commits, in parallel with the confirmation. The
   checkpoint reuses that green when the reuse key excludes the record path.
6. Exec calls in one session reuse one run binary.
7. A delta that the test-gap proof shows is test-only, after a whole-gate green at the
   previous freeze tip, takes a delta checkpoint. The delta checkpoint runs the changed
   packages, root-conformance, conformance, vet, and gofmt. The landing gate always runs whole.

The repaired ticket reruns its own probe. Another ticket's probe carries forward, because
its evidence binds to its own commit tip. Every test-only judgment uses the test-gap proof.

The spec keeps four preconditions. The checkpoint never uses the changed-package selector.
The gate run stays as a native excerpt with its source digest. The selector lists tagged
packages before any skip rule depends on it. The per-ticket check floor moves to a chunk-level floor.

The FT438 exemption is a prerequisite of change 3, so the spec takes it as its first chunk.
A file-overlap skip and a general carry-forward engine stay out of scope.

The spec decides two open points. One point is whether a chunk keeps a cap of four tickets
when the restage is gone. The other is whether an author dispatch, not only a repair,
takes one preflight build.
