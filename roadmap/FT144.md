**FT144 (MEDIUM) — kit specs have two audiences and the discipline names neither.**

A kit spec is read by this repository and by every repository that links the kit.
The authoring discipline distinguishes them nowhere. `craft-spec` gains a
two-audience edge-inventory prompt, so a spec states which audience each behavior
serves. This includes the edge it keeps missing: an absent tickets directory and
an empty one are different states with different correct answers.

Separately, a transaction-shaped spec classifies its verification failures.
Persistence before the oracle runs, interruption inside it, and persistence at
the terminal step are three different failures and want three different rows.

The post-approval-edit question this row used to carry is decided and out of
scope here. Its ruling lives in the decision record. That record also names
where it lands.
