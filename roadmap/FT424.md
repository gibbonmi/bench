**FT424 (MEDIUM) — a chunk gap lands the prepared work of waiting committed outcomes.**

An open build holds the landing window of the default branch. Another landing publishes
only in a chunk gap. The gap opens at a green chunk checkpoint, and the next
`bench record assignment` closes it at once. A parallel session gets no signal that a gap
is open, and the landing has no queue. A spec stage of a waiting committed outcome can
therefore finish its work and still wait until the build completes.

At each chunk checkpoint, the build orchestrator lands each prepared landing of a waiting
committed outcome before it records the next chunk assignment. A spec-stage landing is the
first case. The rule keeps the build-landing-window decision: `main` moves only in a gap,
and the fold that the next dispatch needs takes up the move.

The window opens at `bench commitment start`, before the build dispatches a ticket. A
build must fold `main` before its first chunk anyway, so a landing in that interval costs
the build nothing, but it still takes a reviewer override or a block. The spec decides
whether the interval before the first chunk assignment counts as a gap.

This adds a step to the build procedure, so it needs a spec. FT89 owns the guidance
sentence that lets the spec stage itself run during an open build.
