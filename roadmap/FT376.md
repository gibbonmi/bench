**FT376 (MEDIUM) — the spec stage traces each pinned check, entry read, and derived expectation to its grader before the first review.**

`craft-spec` asks for the cheapest wrong answer for each row. It has no pre-review
check that traces a row through the code that grades it. Review then finds the gap.

Before the first review charge, the spec author makes three checks:

- A pin row quotes its comparison operator.
- The reader sweep lists each unexported read below an entry without an internal form.
- No expectation comes from the code under test.

A spec that consolidates repeated rules includes a table of each site's old rule and new rule.
Each changed cell maps to an acceptance row, a flagged addition, or a Won't handle line.
The author checks every quantified obligation at each affected site and across all tickets.

The caller sweep uses `bench consumers` for each changed function, including unexported functions.
For each new workflow step, the author traces every write through the digests that later checkpoints compare.
