**FT341 (HIGH) — a Bench verb reaches a worktree only through `--in`: exec refuses a Bench child, and directory inference ends.**

Each public registry leaf declares `tree` or `repository` scope, and a conformance check
refuses an undeclared leaf. A tree-scoped verb takes `--in <label|primary>` as the first
argument after its leaf and runs as one child in that tree target. Each tree-scoped response
starts with one `tree[1]{target,head,dirty}` row. In the kit repository, a worktree target
runs its own worktree build, and a missing or stale build refuses. `internal/canonicalpath`
owns the path derivation, and the gate kit-source path uses it.

Directory inference and the exec route for Bench commands remain. The residual is spec B. In
one landing, `bench worktree exec` refuses a Bench child, directory inference ends, and every
hook and skill that calls Bench moves to `--in`. So no build grades the primary checkout by
mistake. `bench gate-prose` is plumbing with a root operand today; spec B decides whether it
resolves its subject from the named tree.

Spec B honors these closed decisions:

- `--in` accepts a worktree label or `primary` only. A path operand exits 2. A
  repository-scoped leaf that gets `--in` exits 2. No environment variable selects a tree
  target.
- With no `--in`, a tree-scoped verb targets the primary checkout, also from inside a pool
  worktree.
- A leaf that reads, grades, or writes tracked content is tree-scoped. The lifecycle verbs are
  repository-scoped and keep their positional `<target>`. Plumbing leaves keep their root
  operand and their inherited kit and run-binary routing.
- `bench worktree exec <label> -- bench <verb>` refuses and prints `bench <verb> --in <label>`.
  Exec detects a Bench child with the parser of the follow-on guard, and it keeps running other
  commands.
- An exit-2 grammar refusal prints no tree row. Each nested Bench call prints its own row.
  Exactly one active label match wins the lookup.
- A `bench worktree list` filter by spec is out of scope; FT125 owns it.

Two defects wait for spec B:

- The shared tree-child runner starts the child in its own process group. A child that reads
  the terminal stops, and the parent waits with no deadline. The `--in` route and the exec
  route both reach this runner. Fix it once, and pin the fix with a test that runs a
  terminal-reading child. FT254 owns the stdin decision of an exec child, so spec B takes that
  decision with this fix.
- A label collision has no `--in` address. `bench worktree create` accepts a duplicate label,
  and spec B removes the exec route by assignment id. The options are an assignment id as a
  third `--in` value, or a duplicate-label refusal at create. The reviewer leans to the refusal
  at create, because the `--in` value set is closed.
