**FT98 (MEDIUM) — one preserve-then-discard primitive; four faces.**

The landed-proof, branch-retirement, and recovery-discard faces have shipped.
What remains is one primitive's unfinished edges. A `--fingerprint-only` plan
view exists nowhere in the tree. The stale-fingerprint retire check also has
no runtime-contract coverage.

Orphan deletion also does not carry the planned
object id through a compare-and-swap. So a ref that moved between plan and
apply is deleted against a stale reading. The fingerprint field is also emitted
inconsistently across plan rows. The refusal that recommends `--discard-ignored`
must also warn that adding it invalidates the fingerprint it just printed.

`bench worktree clean --landed --full` plans recover-remove for every landed
worktree and applies each plan under its own fingerprint in one verb.

A legacy `cleanup-pending` assignment with no request token has no safe
recovery today. `list` and `clean --landed` print and execute that recovery.

The same plan owner supports a dirty worktree whose diff a named commit already
carries. It proves that containment before it offers a recoverable discard.
A multi-worktree clean plan also keeps each unaffected fingerprint valid after
one sibling is removed.

One worktree probe copies the target path aside and restores `HEAD` before the
next probe. The same owner keeps the preserved copy and the restore route.

The probe face needs a new `bench worktree` subcommand, a declared seam, so the
row is not a light-path ticket.
