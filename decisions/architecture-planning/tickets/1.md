# How should preflight handle fence and premise knowledge?

Blocked by: none
Type: Grill

### Question

How should preflight handle fence and premise knowledge?

### Answer

For FT293, let preflight derive mechanical closure proposals from canonical registries and real callers.
Keep the approved spec fence and ticket Writes lines as the authorization source.
A proposal does not widen either fence automatically.

The author must incorporate the required paths before dispatch.
Preflight then verifies the complete explicit fence and its current source premises.
Show the reason and owning source for each required path.
Support a deleted-path marker against the pinned before-state.
Do not require a deleted path to exist in the after-state.

Separate grammar changes from unrelated changes in the same package.
Registry closure must follow actual grammar obligations rather than package membership alone.
A derived count, glob list, or headroom fact must name the source tip.
Unknown premises must remain unknown or refused, never guessed green.
