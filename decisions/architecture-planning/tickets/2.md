# When may the staleness pass be omitted?

Blocked by: none
Type: Grill

### Question

When may the staleness pass be omitted?

### Answer

Implement FT375 in the existing preflight owner.
Project changed fenced paths, unresolved cited symbols, and mismatched existing or planned tests.
Read them against the same pinned source identity.

Only omit the manual staleness pass when every required row is green and the drift set is empty.
Missing metadata, unresolved source, or unsupported citation forms require a diagnostic.
They must not become an empty drift result.

Tests must change a cited symbol, remove an existing test, and add a supposedly planned test.
Each case must reach the production preflight response.
Keep semantic review for changed requirements and actual drift.
This changes the need for repeated mechanical reads, not the authority of review.
