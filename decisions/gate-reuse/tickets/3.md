# Does the grade key bind the run binary digest in place of the baseline runner identity?

Blocked by: #1, #2
Type: Grill

### Question

ADR 16 keys green evidence to the prospective tree and the baseline runner identity.
The criterion `FT314-gate-reuse.grade-key` names a run-binary digest.
In the kit, the baseline runner identity is the digest of the identity root's declared build inputs.
So a spec that changes Go code never reuses its checkpoint green at landing: 1 of 36 spec landings since 2026-10-01 changed no build input.
Decide the member that replaces the baseline runner identity.
Decide how the key keeps the ADR 16 guard that candidate code never authorizes its own publication.

### Answer

The grade key binds the run binary digest and the running executable's digest.
These two members replace the baseline runner identity and the policy version.
A run that selects no run binary frames one stable value for that member.

The landing's own broker digest is a key member, so the landing finds only a grade that the same broker wrote.
A checkpoint under a worktree's candidate build keys to another digest, so its green never answers the landing.
This keeps the ADR 16 guard by construction, with no trust in a record field.
ADR 16's evidence sentence changes to name the grade key in place of the baseline runner identity.
