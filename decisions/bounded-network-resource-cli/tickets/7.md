# What is the one CLI argument grammar?

Blocked by: none
Type: Grill

### Question

Parsing is per-command and inconsistent. Trailing garbage is variously
accepted; help sometimes exits 2. There is no `--` for leading-dash commit
paths. Directory commit paths do not authorize children, and coverage
resolves slugs CWD-relative.

### Answer

A small shared parsing helper (hand-rolled, beside the existing `toon.Usage`
helpers; no third-party CLI framework) owns the grammar. Every Go subcommand
routes through it. Exact arity applies, with trailing garbage rejected as a
usage error (exit 2). `help`/`--help`/`-h` always exit 0. `--` ends flag
parsing, so leading-dash paths stay expressible. Spec-slug fallbacks resolve
from the repository root everywhere; `coverage` adopts the `spec` package's
root anchoring.

`bench commit` path arguments gain the conventional directory grammar:
naming a directory authorizes its changed children. **[veto — widens what a
commit path stages]**. Hostile filenames (dashes, spaces, globs) are
contract-tested.
