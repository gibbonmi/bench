# How does the exec route for Bench commands end?

Blocked by: #1, #2
Type: Grill

### Question

Today a caller grades a worktree through `bench worktree exec <label> -- bench
<verb>`. After `--in` exists, what does that route do? How does the change reach
callers without a build that grades the wrong tree?

### Answer

- `bench worktree exec <label> -- bench <verb>` refuses and prints `bench <verb> --in <label>`. Exec keeps running commands that are not Bench commands.
- Spec A adds `--in` and keeps directory inference. A tree-scoped leaf with no `--in`, whose directory is inside a pool worktree, still targets that worktree.
- Spec B removes directory inference, adds the exec refusal, and migrates every hook and skill, all in one landing. No build between the two specs grades the primary checkout by mistake.
