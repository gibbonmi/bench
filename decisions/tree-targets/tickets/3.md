# Which running executable serves a named tree target?

Blocked by: #1
Type: Grill

### Question

A linked worktree has no untracked binary, so the wrapper runs the primary
checkout's executable. Registries compiled into that executable can disagree
with the worktree. Which running executable serves `bench <verb> --in <label>`?

### Answer

- When the tree target is a worktree of a Bench kit source checkout, its worktree build is the running executable.
- A worktree build is stale when its seal does not agree with the worktree's build inputs. When the build is missing or stale, the verb refuses before it runs and prints `bench worktree build <label>`. An uncommitted Go edit makes the build stale. The reviewer accepts one rebuild call after each Go edit.
- A worktree of a linked project repository keeps the installed executable, because that repository compiles no Bench registries of its own.
- The gate still builds its own run binary. The worktree build does not become a run binary.
