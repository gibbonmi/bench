# Which leaves are tree-scoped, and where is that declared?

Blocked by: none
Type: Grill

### Question

The command registry has no scope field. Which predicate classifies a leaf,
where does the declaration live, and which leaves stay outside the `--in`
contract?

### Answer

- Each public registry leaf, down to each subverb leaf such as `worktree list`, declares `tree` or `repository`. A conformance check refuses a public leaf with no declaration. The `--in` grammar and help derive from that field.
- A leaf is tree-scoped when it reads or grades tracked content of one checkout: source, configuration, specs, roadmap, or registries. A leaf is repository-scoped when it reads only Git refs, the worktree ledger, or git-ignored capture files. For example, `roadmap` is tree-scoped, and `idea` is repository-scoped.
- The worktree lifecycle verbs (`worktree build`, `path`, `exec`, `land`, `release`, and their siblings) are repository-scoped. They keep their positional `<target>` operand.
- Plumbing leaves, the hook verbs and gate internals such as `gate-phases`, are outside the contract. They keep their explicit root operand and their inherited `BENCH_KIT` and `BENCH_RUN_BINARY` routing. The rule that no environment variable selects a tree target governs only caller-facing selection.
