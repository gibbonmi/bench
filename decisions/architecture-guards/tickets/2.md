# How much of the degraded shell hook should remain?

Blocked by: none
Type: Grill

### Question

How much of the degraded shell hook should remain?

### Answer

Retain the coarse degraded hook for this migration.
It refuses recognized Git invocations while allowing supported non-Git recovery commands.
Do not replace it with blanket refusal of every shell command.

Remove the permissive malformed-input fallback.
If the degraded parser cannot establish the supported command structure, refuse with a parse-repair diagnostic.
The current whitespace fallback can keep an attached separator inside one word.
See `.bench/hooks/block-dangerous-git.sh:294`.

The core and degraded hook remain separate implementations because the latter runs without the core.
Keep their independent degraded-entry tests as the justification for that duplication.
Do not shrink the hook by deleting a recognized dangerous-command case.
