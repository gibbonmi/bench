# Which strict reader should each caller use?

Blocked by: none
Type: Grill

### Question

Which strict reader should each caller use?

### Answer

Use the existing jsonfile owner.
Use DecodeDocument for a complete user-authored JSON document.
Use Decode for a persisted record whose contract requires a final newline.
Use DecodeExactDocument only when exact key spelling belongs to the schema contract.
The distinctions are explicit at `internal/jsonfile/decode.go:14`.

First repair the vulnerability exception parser.
Its second decode only rejects a nil error at `internal/releasepreflight/vulnerability.go:104`.
A malformed suffix or incompatible second value can therefore escape that check.

Require complete consumption, duplicate-key rejection, and unknown-field rejection for exception documents.
Retain valid trailing whitespace and the existing exception semantics.
Test malformed suffixes, second values, duplicate keys, missing files, and valid empty policies through the real validator.
Do not impose persisted-record newline framing on that file.
