# What should shared file replacement guarantee?

Blocked by: none
Type: Grill

### Question

What should shared file replacement guarantee?

### Answer

Select one durable file-replacement owner in a leaf package.
It writes a temporary regular file beside the destination.
It applies the requested mode, synchronizes the file, closes it, renames it, and synchronizes the containing directory.

Keep caller-owned mode, payload validation, destination authority, and sentinel translation.
A failed synchronization is a failure, not successful durability.
After rename, an error must report that the new file may already be visible.
Do not claim that the old bytes remain after every failure.

The gate supplies an existing strong contract at `internal/gate/verdict.go:88`.
The record writer lacks the directory step at `internal/reviewrecord/write.go:92`.
Treat that stronger guarantee as an explicit behavior change in its own spec.

Keep directory exchange, lock protocols, and evidence promotion outside this file helper.
Tests must inject failures before and after rename and assert the resulting visible state.
Platform checks must establish the supported synchronization behavior before implementation acceptance.
