# Should these primitives share one implementation project?

Blocked by: none
Type: Grill

### Question

Should these primitives share one implementation project?

### Answer

Split the work into three independently useful outcomes.
Repair strict JSON first.
Then consolidate shell argument production and durable file replacement as separate specs or review chunks.

Neither later decision is a prerequisite for the exception-parser repair.
Keep caller-specific error categories and existing refusal tests.
A shared helper test cannot prove that the production caller uses it.
Attach a bypass mutation to each migrated caller family.
