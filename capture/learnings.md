# Learnings — usage journal

- 2026-08-07 — **Repair-round bookkeeping pays full gates the lifecycle was built to avoid.** During the pre-push-guard-visibility close-out, every repair round had to land its ticket *files* on main through `bench commit` before `assign` would accept them: three repair rounds cost three ~10-minute full-gate runs to commit markdown, while the sixteen code checkpoints and integrations correctly paid zero. Two more gates were wasted on a mid-run spec amendment and its forced revert (see next entry). Right behavior: lifecycle bookkeeping should be gate-free until the terminal promote, matching the contract the lifecycle already gives code. Proposed rule change (reviewer decision): either let `bench spec build assign` accept a staged-but-uncommitted ticket and make `promote`'s squash land ticket files, or give `bench commit` a docs-scoped tier that skips code phases for diffs the code checks cannot observe.
- 2026-08-07 — **The run pins staged spec content; a mid-run amendment is unsupported.** A reviewer-approved spec amendment (clean-skip predicate) was committed mid-run and every lifecycle operation refused with `staged spec no longer matches recorded subject`; the amendment had to be reverted (one wasted gate each way) and parked until after terminal promotion. Right behavior: check the `SpecTip` precondition before landing any spec edit while a run is active; park amendments in the scratchpad and re-land them in the closing commit. Proposed rule change: none needed if the gate-free-bookkeeping change above lands with an explicit `spec build` amendment operation; otherwise document the pin in the implement-spec phase doc.
- 2026-08-07 — **Ticketless fixes in looped repair cycles need structural enforcement.** An earlier looped repair cycle landed fixes with no ticket, so no fence or red mutation bound them. The coordinator-derives-ticket-from-receipt discipline held this session, but only because the charge said so. Proposed rule change (reviewer decision): while a spec build run is active, `bench commit` (or the gate) refuses source paths not covered by some ticket's fence under `specs/<slug>/tickets/`, making the ticket requirement self-enforcing instead of prompt-dependent.
