- 2026-08-23  Guard the bench shell-follow-on reflex at the Bash boundary, and remove its cause. Agents still append a shell follow-on to a bench command (for example: bench worktree exec "roadmap-drain" -- bench gate --fresh 2>&1 | tail -40), although .bench/BENCH.md forbids it. The rule is prose only, so it does not bind. Every other hard rule in the kit has an enforcement: block-dangerous-git.sh guards Git, check-agent-line.sh guards the tier, stop.sh guards the red gate. The no-follow-on rule has none. The reviewer states the scope exactly: a bench command takes no added option, no pipe, no redirection, and not even an &&. A bench response is a non-standard response, and it is designed to be read on its own. Observed root cause: the agent appends the follow-on BEFORE it knows the output length. A live instance piped 'bench gate --help', whose real output is one line. So the follow-on is insurance against an unbounded read, not a response to a measured one. Prose cannot reach a reflex. Two proposed levers, in priority order. First, add a PreToolUse:Bash guard beside block-dangerous-git.sh, as a thin shim over a bench core verb, with the same fail-open rim. It denies a Bash command that invokes bench and also carries a pipe, a redirection, an &&, a semicolon, or an appended subcommand. Its deny message must state that the bench response is complete and self-contained, because a bare denial makes the agent retry a variant. Second, teach the reason wherever the rule appears. The agent adds the follow-on because it treats bench like an ordinary shell tool with unbounded output. Once the agent knows a bench response is already bounded and complete, the insurance has no reason to fire. Do NOT answer this by adding projection options such as a --brief flag; that concedes the premise the rule denies. Note one parsing requirement: in the example above, the redirection and the pipe sit outside the --, so the shell applies them to bench worktree exec itself. The guard must parse the whole command line, not only the segment after the --.
